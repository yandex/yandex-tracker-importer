# Экспортер из Bitrix24 в формат для универсального импортёра в Yandex Tracker

Инструмент выгружает задачи, рабочие группы и потоки Bitrix24 в YAML-формат, совместимый с универсальным
импортёром в Yandex Tracker [`yandex-tracker-importer`](https://github.com/yandex/yandex-tracker-importer).
Описание форматов выходных файлов см. в документации импортёра.

> **ИИ-агентам:** пошаговый runbook по проведению миграции — в [`AGENTS.md`](AGENTS.md).

## Быстрый старт

### 1. Соберите Docker/Podman образ

**Docker:**

```bash
docker build -t bitrix-exporter:latest .
```

**Podman:**

```bash
podman build -t bitrix-exporter:latest .
```

### 2. Подготовьте рабочую директорию

Рабочая директория должна содержать каталог `configs/`:

```
configs/
├── webhook_url.cfg         # входящий вебхук Bitrix24
├── tasks_filter.yaml       # какие задачи выгружать, {} — все
├── projects_filter.yaml    # какие рабочие группы выгружать, {} — все
└── .projects               # или: id рабочих групп по строке, выгружаются вместе с задачами
```

Каталоги `data/` (результат), `info/` (списки для сопоставлений), `state/` (состояние для повторного запуска) и
`logs/` создаются автоматически.
Чтобы доэкспортировать рабочие группы, допишите их в `configs/.projects` и запустите экспорт снова: выгрузятся
только новые группы. Подробнее о файлах и фильтрах — в
[документации](docs/index.md#использование-и-конфигурация).

### 3. Запустите экспортер

Экспортер работает в контейнере и использует примонтированную рабочую директорию `/work`. Команда запускается
из каталога, где лежит папка `configs`.

**Docker:**

```bash
docker run --rm \
  --user "$(id -u):$(id -g)" \
  -v "$(pwd)":/work \
  -w /work \
  bitrix-exporter:latest
```

`--user` запускает экспорт от вашего пользователя, чтобы он мог писать в рабочую директорию.

**Podman:**

```bash
podman run --rm \
  --userns=keep-id \
  -v "$(pwd)":/work \
  -w /work \
  bitrix-exporter:latest
```

После выполнения данные для импорта появятся в `data/`, списки пользователей и отделов для сопоставлений —
в `info/`, состояние для следующего запуска — в `state/`, журнал — в `logs/`. При ошибках экспорт завершается
с кодом 1 и выводит сводку.

### Запуск без контейнера

Нужен Python 3.12 или новее. `<каталог экспортёра>` — каталог с `requirements.txt` и папкой `exporter/`.
Команда запускается из рабочей директории с папкой `configs`:

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r <каталог экспортёра>/requirements.txt
PYTHONPATH=<каталог экспортёра> python -m exporter
```
