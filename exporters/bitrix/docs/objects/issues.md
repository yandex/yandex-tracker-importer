# Задачи

Задачи Bitrix24 выгружаются в задачи Yandex Tracker.

## Соответствие полей

| Bitrix24                        | Yandex Tracker                                  |
|---------------------------------|-------------------------------------------------|
| Статус                          | Статус, у завершённой и отклонённой — резолюция |
| Дата и автор закрытия           | `resolvedAt`, `resolvedBy`                      |
| Приоритет                       | Приоритет                                       |
| Родительская задача             | Связь `is subtask for`                          |
| Чек-листы                       | `checklistItems`: пункты всех чек-листов одним списком, см. «Особенности экспорта» |
| Комментарии чата задачи и файлы в них | `comments`, файлы — во вложениях задачи со ссылкой из комментария |
| Результаты задачи и файлы в них | `comments` с заголовком «Результат от 10.11.2026 18:12», файлы — во вложениях задачи со ссылкой из комментария |
| Затраченное время               | `worklogs`: дата, на которую списано время, длительность, комментарий, автор, время создания — остановка таймера или ввод записи |
| Плановая трудоёмкость           | `originalEstimation`                            |
| Плановые даты начала и завершения | `start`, `end`; фактическая дата начала не выгружается |
| Теги                            | `tags`                                          |
| Стадия задачи рабочей группы    | Поле `kanbanStatus`: стадия канбана группы, у задачи спринта — стадия доски спринта, у задачи бэклога не заполняется; задача без стадии — в первой стадии |
| Story points задачи скрам-группы | `storyPoints`                                  |
| Спринт и бэклог скрам-группы    | `boards` — доска группы, `sprint` — спринт; у задачи бэклога спринта нет, см. [скрам](./scrum.md) |
| Эпик задачи скрам-группы        | Связь `has epic` с эпиком из очереди `EPIC`, см. [скрам](./scrum.md) |
| Соисполнители                   | Поле `accomplices`                              |
| Пользовательское поле задачи    | Глобальное поле                                 |
| Рабочая группа                  | Проект                                          |

## Статусы и резолюции

| Статус Bitrix24                 | Статус Трекера | Резолюция |
|---------------------------------|----------------|-----------|
| Новая, Ждёт выполнения          | `open`         |           |
| Выполняется                     | `inProgress`   |           |
| Ждёт контроля                   | `inReview`     |           |
| Отложена                        | `onHold`       |           |
| Завершена                       | `resolved`     | `fixed`   |
| Отклонена                       | `cancelled`    | `wontFix` |

Статусы и резолюции выгружаются в `statuses.yaml` и `resolutions.yaml` со стандартными ключами Трекера.
Время и автор резолюции — дата и автор закрытия задачи; каждое из них без значения заменяется датой или автором
последнего изменения. Без даты или автора резолюция не выгружается, в журнале — предупреждение.

## Приоритеты

| Bitrix24 | Yandex Tracker |
|----------|----------------|
| Низкий   | `minor`        |
| Средний  | `normal`       |
| Высокий  | `critical`     |

## Пользовательские поля

| Тип в Bitrix24 | Тип глобального поля                     |
|----------------|------------------------------------------|
| Строка         | `string`                                 |
| Ссылка         | `uri`                                    |
| Целое число    | `integer`                                |
| Число          | `float`                                  |
| Дата           | `date`, дата в UTC                       |
| Дата и время   | `datetime`                               |
| Да/Нет         | `string` со списком значений `Да`, `Нет` |
| Список         | `string` со списком значений поля        |

Множественный список выгружается полем `array` со списком значений, остальные множественные поля — полем `text`,
по значению в строке. Значение списка, которого нет среди вариантов поля, не выгружается, в журнале —
предупреждение. Поля других типов не выгружаются, в журнале — предупреждение. В `global_fields.yaml` попадают поля,
заполненные хотя бы в одной задаче текущего или прежних запусков экспорта в тот же каталог.

## Автоматически генерируемые поля

- **Ключ задачи**: `<ключ_очереди>-<номер_задачи>`.
- **Тип задачи**: `task`.

## Особенности экспорта

1. Имя файла вложения дополняется id вложения: `document.pdf` → `document_123.pdf`.
2. Чек-листы задачи объединяются в один список в порядке чек-листов и пунктов, вложенные пункты идут за
   родительским. Если непустых чек-листов несколько, пункт начинается с названия чек-листа, когда текст с ним
   укладывается в ограничение Трекера на длину пункта (2000 единиц UTF-16), иначе — без названия, в журнале —
   предупреждение. Название по умолчанию выгружается как «Чек-лист <n>» на русском. Исполнитель пункта — первый его
   соисполнитель, который также исполнитель или соисполнитель задачи; наблюдатели и остальные соисполнители пункта
   не переносятся. Пункт, чей чек-лист не найден, выгружается в конце списка без названия чек-листа, в журнале —
   предупреждение.
   Импорт принимает не больше 100 пунктов в задаче; при большем числе в журнале экспорта — предупреждение.
3. Связь с родительской задачей, которой нет ни в текущем запуске экспорта, ни в `data/queues`, не создаётся, в
   журнале — предупреждение. Подзадача не выгружается, если родительскую задачу текущего запуска не удалось
   выгрузить или её не вернул API, а также если родительская задача из `data/queues` не читается или есть в
   нескольких очередях.
4. Дата связи с родительской задачей — более поздняя из дат создания подзадачи и родительской задачи, автор —
   автор подзадачи.
5. Задачи без потока помещаются в очередь с ключом `TASK`.
6. Комментарии берутся из чата задачи и из ленты комментариев задачи. Системные и удалённые сообщения чата
   («начал выполнять», «изменил стадию», «сообщение удалено» и т. п.) не выгружаются. Файл сообщения или файл
   задачи, недоступный через API (удалён, нет доступа), не выгружается, в журнале — предупреждение.

   Каждый результат задачи выгружается отдельным комментарием. Комментарий начинается с заголовка с датой
   и временем результата: «Результат от 10.11.2026 18:12». Время в заголовке — как у результата в Bitrix24.
   Автор и время комментария — автор и время результата. Если Bitrix24 не отдал результаты задачи, задача
   выгружается без них, в журнале — предупреждение.
   Сообщение чата, из которого сделан результат, отдельным комментарием не выгружается: Bitrix24 копирует его
   в результат.
7. Время изменения задачи — не раньше времени её комментариев, вложений и связей: импорт отклоняет комментарий,
   файл и связь позже `updatedAt` задачи.
8. Разметка BBCode переводится в Markdown: жирный, курсив, зачёркнутый, ссылки, упоминания, цитаты, списки, в том
   числе вложенные, блоки кода, таблицы, изображения; теги распознаются в любом регистре, содержимое блоков кода
   не преобразуется. Ссылка `[DISK FILE ID=…]` вне блоков кода заменяется ссылкой на вложение; ссылка на файл,
   которого нет во вложениях задачи, остаётся без изменений, в журнале — предупреждение. В ленте комментариев
   задачи заменяются только ссылки вида `n<id>`. Файл, прикреплённый к задаче рабочей группы, Bitrix24 хранит
   копией «Копия <имя>»; если текст ссылается на исходный файл и среди файлов задачи ровно одна копия с тем же
   именем и размером, вложение получает исходное имя.
9. Не переносятся: связи диаграммы Ганта (REST API не отдаёт их), история изменений.
