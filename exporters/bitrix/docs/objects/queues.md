# Потоки

При экспорте из Bitrix потоки преобразуются в очереди Yandex Tracker с сохранением основной информации и структуры.

## Автоматически генерируемые поля

- **Ключ очереди**: название потока латиницей без цифр, знаков и пробелов, не длиннее 15 букв, например «Закупки
  оборудования» → `ZAKUPKIOBORUDOV`. Если ключ занят другим потоком, очередью по умолчанию `TASK` или очередью эпиков
  `EPIC` или не подходит для очереди Трекера (короче двух букв или служебное слово, например `ORDER`), к нему
  добавляются буквы из id потока: цифра 0 — `A`, 1 — `B` и так далее, например поток 17 «Task» → `TASKBH`.
  Ключи выгруженных потоков записываются в `state/flows.cfg` строками `<id потока>:<ключ очереди>`, и при
  поэтапном экспорте поток получает тот же ключ.

  Экспорт перезаписывает этот файл после каждого запуска, комментарии в нём не сохраняются.

  Чтобы задать потоку свой ключ, добавьте строку в `state/flows.cfg` до его выгрузки, например `17:PURCHASE`. Если
  поток уже выгружен, после смены ключа удалите каталог прежней очереди из `data/queues` и выгрузите задачи потока
  заново целиком. Иначе часть задач останется в прежней очереди или пропадёт из выгрузки.

  Если в `state/flows.cfg` ключ не подходит для очереди, ключ или поток повторяется, экспорт ничего не выгружает
  и завершается с кодом 1.
- **Рабочий процесс**: стандартные статусы Трекера из [описания задач](./issues.md#статусы-и-резолюции), переход
  из любого статуса в любой, начальный статус — `open`. Для типа `task` доступны резолюции `fixed` и `wontFix`.
- **Стандартный тип задачи при создании**: `task` (задача)
- **Стандартный приоритет задачи**: `normal` (средний)

## Особенности экспорта

1. Экспортируются только те потоки, которые привязаны к экспортируемым задачам.

2. Владельцем очереди становится владелец потока.

3. Участники очереди — пользователи из команды потока и ответственные потока. Импортёр отклоняет очередь с
   участником, которого нет в `mapping/users.cfg` и в организации Трекера.

4. Права очереди — см. ниже.

## Права очереди

Если ставить задачи в поток могут все, права очереди не выгружаются: остаются права по умолчанию.

Если ставить задачи в поток может только список пользователей и отделов:

- создавать задачи в очереди могут пользователи и отделы из этого списка — отделы группами, как в
  [правах проектов](./projects.md#отделы), — и владелец очереди;
- читать и изменять задачи очереди могут все сотрудники: выгрузка выдаёт это право группе «Все сотрудники».

Импортёр ищет группу «Все сотрудники» по названию. Если в организации Трекера есть ещё и отдел с таким названием
(так бывает в организациях Яндекс 360), права может получить отдел, а остальные сотрудники потеряют доступ к задачам
очереди. Чтобы права получила служебная группа, добавьте в `mapping/groups.cfg` строку `Все сотрудники:1` — 1 это
номер служебной группы.

Если пользователя из списка нет ни в `mapping/users.cfg`, ни в организации Трекера, импортёр не выдаёт право на
создание задач никому из списка: создавать задачи сможет только владелец очереди, в журнале импорта — ошибка
`Error updating permissions for queue`.

Из списка тех, кто ставит задачи, переносятся только пользователи и отделы. Если в списке указан другой тип
участника (например, проект) или удалённый отдел, поток и его задачи не выгружаются, экспорт завершается с кодом 1.
