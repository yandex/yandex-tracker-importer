# Проекты

Рабочие группы Bitrix24 выгружаются в проекты Yandex Tracker.

## Соответствие полей

| Bitrix24                        | Yandex Tracker            |
|---------------------------------|---------------------------|
| ID                              | `id` вида `bitrix24-<ID>` |
| Название                        | `summary`                 |
| Описание                        | `description`             |
| Владелец                        | `author`, `createdBy`, `lead` |
| Дата создания                   | `createdAt`               |
| Участники                       | `teamUsers`               |
| Даты начала и окончания проекта | `start`, `end`            |
| Ключевые слова                  | `tags`                    |
| Закрытая или невидимая группа   | `teamAccess: true`        |
| Модераторы                      | Право `GRANT` — управление доступом |
| Отделы закрытой или невидимой группы | Группы с правом `WRITE`, см. «Отделы» |
| Файлы на диске группы           | Вложения                  |

## Особенности экспорта

1. Проект выгружается в каталог `projects/<ID>`.
2. Импортёр находит созданный проект по тегу `imported_<id>`. Префикс `bitrix24-` отличает id групп от id
   объектов из других источников, импортированных в ту же организацию.
3. Выгружаются файлы диска группы, включая вложенные папки. Имя файла дополняется id файла.
4. Выгружаются проекты из `projects_filter` и проекты выгруженных задач.

## Права

Ответственный, права модераторов и права отделов задаются при создании проекта: импортёр не меняет права проекта,
созданного раньше.

## Отделы

Отдел, привязанный к закрытой или невидимой группе, выгружается группой Трекера с правом на изменение проекта. Права
получают участники этой группы в Трекере; сотрудники отдела на момент экспорта выгружаются участниками проекта.
Отделы открытой группы в права не выгружаются: изменять её проект могут все сотрудники.

Группа называется по отделу. Если название отдела на портале не уникально или совпадает с «Все сотрудники», к нему
добавляется название родительского отдела — «Продажи (Северный филиал)», а если и так не различить — id отдела —
«Продажи (42)». Название зависит от отделов портала на момент экспорта: если между этапами поэтапного экспорта
появился одноимённый отдел, тот же отдел во второй выгрузке получит другое название; сопоставьте в
`mapping/groups.cfg` оба названия.

Если отдел, привязанный к группе, удалён, проект не выгружается, экспорт завершается с кодом 1.

Импортёр не создаёт группы, а ищет их в организации Трекера по названию. Отделы из прав экспорт перечисляет в
файле `info/departments.csv` (см. [результат экспорта](../index.md#результат)); если группа в
Трекере называется иначе, сопоставьте её в `mapping/groups.cfg` импортёра:

```
Продажи (Северный филиал):Отдел продаж Север
```

Если группы нет в организации, импортёр всё равно создаёт проект, только без этой группы в правах; в журнале
импорта — предупреждение `Group … is not found`.
