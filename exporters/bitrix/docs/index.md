## Общая информация

Инструмент позволяет экспортировать данные из Bitrix24 в формате YAML, совместимом с универсальным импортёром
в Yandex Tracker [`yandex-tracker-importer`](https://github.com/yandex/yandex-tracker-importer).
Подробные описания форматов файлов можно найти в документации импортёра.

## Использование и конфигурация

Экспорт запускается из рабочей директории с каталогом `configs/` — см. [README](../README.md).
Файлы конфигурации:

| Файл                 | Описание                                         | Пример содержимого                                                                 |
|----------------------|--------------------------------------------------|------------------------------------------------------------------------------------|
| webhook_url.cfg      | Вебхук для экспорта                              | <pre><code>https://b24-xxxxxx.bitrix24.ru/rest/xxx/xxxxxxxxxxxxxxxx/</code></pre>  |
| projects_filter.yaml | Фильтр по которому отобрать проекты для экспорта | <pre><code>ACTIVE: "Y"<br>CLOSED: "N"</code></pre>                                 |
| tasks_filter.yaml    | Фильтр по которому отобрать задачи для экспорта  | <pre><code>STATUS: -2<br>GROUP_ID: 123<br>CREATED_DATE: "2023-01-01"</code></pre>  |
| .projects            | Рабочие группы для экспорта вместе с задачами    | <pre><code>12<br>31</code></pre>                                                   |


Вебхук можно получить во вкладке Приложения -> Разработчикам -> Импортировать/Экспортировать данные. Для вебхука нужно выдать все доступные права.

## Результат

Экспорт пишет результат в каталоги рабочей директории:

- `data/` — данные для импортёра.
- `info/` — списки, по которым удобно заполнить сопоставления импортёра:
  - `info/users.csv` — пользователи из выгрузки: идентификатор, id в Bitrix24, имя, почта. По нему заполняется
    `mapping/users.cfg`: `<идентификатор>:<логин в Трекере>`. Отредактированный файл сохраняйте в UTF-8
    с разделителем-запятой;
  - `info/departments.csv` — отделы из прав проектов и очередей: название, id в Bitrix24, родительский отдел. По нему
    заполняется `mapping/groups.cfg`. Создаётся, если в выгрузке есть отделы.
- `state/` — что нужно следующему запуску, чтобы продолжить выгрузку:
  - `state/flows.cfg` — ключи очередей потоков: строка `<id потока>:<ключ очереди>`, например `17:TASKBH`;
  - `state/projects.cfg` — группы из `configs/.projects`, которые уже выгружены, с фильтром задач, с которым их
    выгрузили, например `12:{"CLOSED": "N"}` или `12:{}` без фильтра. Строку только с id, например `12`, экспорт
    считает выгруженной при любом фильтре и пропускает.

  Подробнее — в разделе [поэтапный экспорт](#поэтапный-экспорт).
- `logs/` — журнал экспорта.

Экспорт завершается с кодом 1, если:
- задача, проект или эпики скрам-группы не выгружены;
- не удалось прочитать или записать файл из `info/` или `state/`, `global_fields.yaml` или `boards.yaml`.

Список сбоев выводится в журнал и в стандартный поток ошибок.

## Поэтапный экспорт

Большой портал удобно выгружать по частям в один и тот же рабочий каталог. Следующий запуск дописывает в `data/`
новые задачи. Выгруженные раньше задачи он не удаляет; если задача выгружается ещё раз, её прежняя копия
заменяется новой.

Выгружать по частям можно списком рабочих групп или фильтром задач.

### Списком рабочих групп

Перечислите id рабочих групп в `configs/.projects`, по одному в строке. Строки с `#` — комментарии:

```
# Склад
12
# Маркетинг
31
```

Экспорт выгрузит эти группы вместе с их задачами и запомнит их в `state/projects.cfg`. Повторный запуск запомненные
группы пропускает. Чтобы выгрузить ещё группы, допишите их id в `configs/.projects` и запустите экспорт снова —
выгрузятся только новые.

Если не удалось выгрузить группу или одну из её задач, группа не запоминается, и следующий запуск выгрузит её
заново. Это касается и подзадач, которые экспорт выгружает ещё раз, чтобы добавить связь с родительской задачей
из группы.

Без `tasks_filter.yaml` выгружаются все задачи групп. Чтобы выгрузить часть задач, добавьте
`configs/tasks_filter.yaml`. Например, только незакрытые задачи:

```yaml
CLOSED: "N"
```

Фильтр применяется к задачам каждой группы из списка. Группу в фильтре указывать не нужно: условие `GROUP_ID`
экспорт заменяет группой из списка. Если поменять фильтр, следующий запуск выгрузит группы заново с новым
фильтром. Задачи, выгруженные с прежним фильтром, из `data/` не удаляются.

Чтобы выгрузить группу заново с тем же фильтром, удалите из `state/projects.cfg` все строки с её id.

Со списком групп:
- не задавайте `configs/projects_filter.yaml`;
- не задавайте в `tasks_filter.yaml` других условий на группу, кроме `GROUP_ID`, например `!GROUP_ID` или
  `@GROUP_ID`.

Иначе экспорт сообщит об ошибке и ничего не выгрузит.

Задачи вне рабочих групп по списку не выгружаются. Для них запустите экспорт без `configs/.projects`, с фильтром
задач.

### Фильтром задач

Без `configs/.projects` экспорт выгружает задачи по `tasks_filter.yaml` и рабочие группы по
`projects_filter.yaml`. Рабочие группы выгруженных задач выгружаются всегда. Запустите экспорт ещё раз с другим
фильтром — в `data/` добавятся задачи по новому фильтру. Какие задачи уже выгружены, экспорт не запоминает: задачи,
которые подходят под оба фильтра, выгрузятся ещё раз.

### Что сохраняется между запусками

- Задачи потока всегда попадают в одну и ту же очередь: ключи очередей хранятся в `state/flows.cfg`.
- Списки в `info/`, `global_fields.yaml` и `boards.yaml` дополняются, а не перезаписываются.
- Связь подзадачи с родительской задачей появляется, если родитель тоже выгружен — раньше или позже подзадачи.
  Если родитель выгружен позже, экспорт выгружает подзадачу ещё раз, уже со связью.
- Задача попадает в `data/queues` целиком или не попадает совсем. Если вложение не скачалось, задача не
  выгружается, а её копия от прошлого запуска остаётся как была.

### Ошибки повторного запуска

- Если файл в `state/` не читается или содержит ошибку, экспорт ничего не выгружает.
- Если не читается файл из `info/`, `global_fields.yaml` или `boards.yaml`, экспорт не перезаписывает этот файл.
- Если `issue.yaml` выгруженной раньше родительской задачи не читается или эта задача есть в нескольких очередях,
  подзадача не выгружается.

Во всех этих случаях экспорт завершается с кодом 1.

## Пользователи

Пользователь выгружается по почте. Пользователь без почты и пользователь, которого не возвращает
`user.get`, выгружается идентификатором `bitrix-user-<id>`. Импортёр отклоняет задачу или проект с пользователем,
которого нет в `mapping/users.cfg` и в организации Трекера.
