# AGENTS.md — руководство для ИИ-агента: миграция YouGile → Yandex Tracker

Ты помогаешь пользователю перенести проекты **YouGile** в **Yandex Tracker**. Этот
инструмент (`yougile_exporter`) выгружает проекты, доски и задачи YouGile в YAML,
совместимый с универсальным импортёром [`yandex-tracker-importer`](https://github.com/yandex/yandex-tracker-importer). Полный конвейер:

```
YouGile API  →  yougile_exporter (этот проект)  →  data/*.yaml  →  yandex-tracker-importer  →  Yandex Tracker
```

Экспортер **только читает** YouGile и пишет файлы — ничего не меняет ни в YouGile,
ни в Трекере. Заливкой в Трекер занимается отдельный импортёр `yandex-tracker-importer`.

---

## Что спросить у пользователя

1. **Ключ API компании YouGile** — см. «Получение ключа API». Вместо ключа можно взять
   логин, пароль и точное название компании: экспорт возьмёт существующий ключ компании.
   Если у компании нет ключа, выпусти его.
2. **Какие проекты переносить** — можешь помочь выбрать (см. «Шаг 1»).
3. **Префикс номеров задач** каждого проекта (`MKT` для задач `MKT-12`) — API его не
   отдаёт; предложи по задачам проекта (см. «Шаг 1») и подтверди у пользователя.
4. **Часовой пояс компании** (IANA, например `Europe/Moscow`) — для дат задач со временем;
   по умолчанию UTC.
5. **Ключи очередей** в Трекере, если префикс не из заглавных латинских букв или ключ в
   Трекере уже занят: они задаются на шаге импорта в `mapping/queues.cfg`.

> Ключ API и пароль — секреты: не выводи их в логи, не коммить в репозиторий. Ключ,
> выпущенный для миграции, предложи удалить после неё. Ключ, найденный по логину и паролю,
> может использоваться другими интеграциями компании.

## Получение ключа API

Ключ выпускается запросом к API YouGile по логину и паролю пользователя компании:

```bash
# 1. ID компании — поле id нужной компании в ответе
curl -X POST https://ru.yougile.com/api-v2/auth/companies \
  -H 'Content-Type: application/json' -d '{"login": "<логин>", "password": "<пароль>"}'
# 2. ключ — поле key в ответе; его записать в configs/token.cfg
curl -X POST https://ru.yougile.com/api-v2/auth/keys \
  -H 'Content-Type: application/json' \
  -d '{"login": "<логин>", "password": "<пароль>", "companyId": "<id компании>"}'
```

## Шаг 1. Discovery — помоги выбрать проекты и префиксы

```bash
curl -H "Authorization: Bearer <ключ>" "https://ru.yougile.com/api-v2/projects?limit=1000&offset=0"
curl -H "Authorization: Bearer <ключ>" "https://ru.yougile.com/api-v2/boards?projectId=<id проекта>&limit=1000&offset=0"
curl -H "Authorization: Bearer <ключ>" "https://ru.yougile.com/api-v2/columns?boardId=<id доски>&limit=1000&offset=0"
curl -H "Authorization: Bearer <ключ>" "https://ru.yougile.com/api-v2/task-list?columnId=<id колонки>&limit=1000&offset=0"
```

Ответ — `content` и `paging`; пока `paging.next` равно `true`, запрашивай следующую
страницу с `offset`, увеличенным на 1000.

Проект — это `id` + `title`. Префиксы проекта — префиксы поля `idTaskProject` задач его
колонок (`MKT-12` → `MKT`). Номер, равный полю `idTaskCommon` той же задачи (вида
`ID-17`), префикса проекта не содержит — его не учитывай. Самый частый
префикс — только подсказка: перенесённые из других проектов задачи сохраняют свой номер,
у пустого проекта задач нет. Покажи пользователю префиксы с числом задач и спроси префикс
проекта. Предложи строки `<префикс>:<название проекта>`; название указывается точно, как
в YouGile.

## Шаг 2. Собери образ

```bash
docker build -t yougile-exporter:latest .    # либо podman build …
```

## Шаг 3. Подготовь `configs/` и запусти

Запускай из отдельного рабочего каталога: экспорт читает `configs/` и пишет `data/`,
`logs/` и `state/` в текущий каталог.

```
configs/
├── token.cfg      # ключ API компании YouGile (или login.cfg, password.cfg, company.cfg)
├── projects.cfg   # <префикс>:<название проекта>, по строке на проект
└── timezone.cfg   # необязательный: часовой пояс, например Europe/Moscow
```

```bash
docker run --rm --user "$(id -u):$(id -g)" -v "$(pwd)":/work -w /work yougile-exporter:latest
# либо: podman run --rm --userns=keep-id -v "$(pwd)":/work -w /work yougile-exporter:latest
```

Повторный запуск в тот же каталог обновляет выгрузку: `projects.cfg` каждый раз перечисляет
все проекты переноса, ключи задач прошлой выгрузки хранятся в `state/yougile_keys.cfg` и
сохраняются. Не удаляй `state/`: без него ключи перенумерованных задач посчитаются заново,
и импорт создаст копии. Задачи, импортированные раньше, повторный импорт не меняет:
повторная выгрузка переносит новые задачи и проекты.

**Совет:** начни с ОДНОГО проекта в отдельном рабочем каталоге, проверь результат и
импортируй его только в тестовую организацию. Для рабочей организации начни в новом
рабочем каталоге со всеми проектами в `projects.cfg`; чтобы добавить проект позже, добавь
строку и запусти экспорт в том же каталоге.

## Шаг 4. Проверь выгрузку

Код завершения и вывод:
- **код 1 и «Nothing is exported»** — экспорт ничего не записал в `data/`. Исправь ошибки,
  перечисленные перед этим сообщением, и запусти снова. Полный список проверок — в
  [`README.md`](README.md);
- **код 1 и «The export is incomplete»** — часть данных не выгрузилась, список выведен
  перед сообщением, подробности — в `logs/export-<дата>.log`. Запусти экспорт снова.
  Если после повтора список тот же (например, недоступный пользователь или файл с отказом
  в доступе), покажи его пользователю: он решает, импортировать ли выгрузку без этих данных;
- **код 1 с трассировкой** — сбой вне проверок (например, нет места на диске): устрани
  причину и запусти снова;
- **сводка префиксов** вида `YouGile project 'X' → queue MKT; task keys in its columns:
  MKT — 12, WEB — 1` — задачи с префиксом, отличным от указанного в `projects.cfg`, получают
  новые номера. Сверь префикс до импорта в рабочую организацию: если он указан неверно,
  исправь `projects.cfg` и выгрузи в новом рабочем каталоге;
- **«N tasks have keys other than their YouGile numbers»** — задачи с номером другого проекта, подзадачи без номера и
  задачи, чей номер прошлая выгрузка отдала другой задаче; старые и новые номера — в
  `logs/renumbered-<дата>.csv`;
- **`exported earlier as … gets the key …`** — задача оказалась в другой очереди
  (перенесена в YouGile в другой проект сама или вместе с родителем) и получила ключ новой
  очереди; задача под прежним ключом остаётся в Трекере.
  Покажи такие задачи пользователю;
- **`is not exported: another task of the queue has the same key`** — у двух проектов
  YouGile один префикс, такая задача не выгружена. Код завершения при этом 0: проверяй
  вывод и журнал. Не переходи к импорту: предложи пользователю сменить префикс одного из
  проектов в YouGile и выгрузи заново.

Файлы:
- `data/queues/<KEY>/queue.yaml` — очередь, статусы, воркфлоу, локальные поля;
- `data/queues/<KEY>/<KEY>-N/issue.yaml` — задачи (рядом `attachments/`);
- `data/{statuses,resolutions,global_fields,boards}.yaml` — общие справочники и доски.

Открой пару `issue.yaml` и убедись, что `summary`/`status`/`assignee`/`comments`
выглядят осмысленно.

## Шаг 5. Импорт в Tracker (через `yandex-tracker-importer`)

Готовые `data/` заливает импортёр `yandex-tracker-importer`. Перед импортом прочитай его runbook
[`AGENTS.md`](https://github.com/yandex/yandex-tracker-importer/blob/main/AGENTS.md): там `config.yaml`, доступы,
тестовый импорт и проверка результата. Импорт читает `data/` из своего рабочего каталога:
скопируй туда выгрузку или укажи её каталог флагом `--data-dir`.

Повторная выгрузка из того же рабочего каталога экспорта импортируется в ту же
организацию: задачи с ключами прошлой выгрузки импорт находит и не создаёт заново.

Для выгрузки YouGile нужны файлы сопоставлений в `mapping/`:

- `users.cfg` — e-mail YouGile → логин Трекера для каждого пользователя, который
  встречается в выгрузке. Пользователь без почты или удалённый из компании выгружен как
  `yougile-user-<id>` — его тоже нужно сопоставить. Это ключевой ручной шаг;
- `queues.cfg` — префиксы из `projects.cfg`; строка нужна, если ключ очереди в Трекере другой;
- `statuses.cfg` — ключи из `data/statuses.yaml`: транслит названий колонок (например,
  `vRabote`) и служебный закрывающий статус `closed`; их можно сопоставить с существующими
  статусами Трекера;
- `resolutions.cfg` — ключи из `data/resolutions.yaml`: резолюция `fixed` доступна в очередях, у задач резолюции нет;
- `issue_types.cfg` — все задачи выгружаются с типом `task`.

Формат строки — `<ключ в выгрузке>:<ключ в Трекере>`. Строка нужна только для
ключа, который в Трекере другой; сами файлы обязательны.

Сразу после создания очередей Трекер может отклонять задачи с ошибками
«Статус не существует.», «Воркфлоу не существует.» или «Очередь не существует.» в
`logs/import-<дата>.log`. Повтори импорт через 1–2 минуты из того же рабочего каталога
импортёра, сохранив `state/`: созданные объекты не дублируются.

## Карта соответствий (кратко)

| YouGile | Yandex Tracker |
|---|---|
| Проект | Очередь (ключ — префикс из `projects.cfg`) |
| Роли участников проекта | Права очереди: наблюдатель — чтение, сотрудник — ещё создание и изменение, администратор — ещё настройки; пользовательская роль — по её правам на все задачи; импорт снимает права группы «Все сотрудники» |
| Доска | Доска с колонками; доска, единственная в проекте, собирает задачи очереди |
| Колонка | Статус |
| Задача | Задача |
| Подзадача | Задача-подзадача; без колонки — в очереди, статусе и на доске родителя из проекта её номера, иначе первого родителя |
| Выполненная задача | Статус своей колонки, без резолюции |
| Архивная задача | Метка «Архив», не на доске |
| Исполнители / подписчики чата | `assignee` и `followers` |
| Стикер с иконкой приоритета и стандартными значениями | Приоритет |
| Таймтрекинг | `estimation` и `spent` |
| Стикеры | Локальные поля очереди с одним значением; спринт — с датами: `Sprint 1 (24.06–08.07)` |
| Номер задачи | Ключ задачи и глобальное поле «Номер в YouGile» (`yougileKey`) |
| Чат задачи / файлы | Комментарии / вложения |

Полное описание полей и нюансов — в [`README.md`](README.md).

## Ограничения (проговори пользователю заранее)

- **Префикс проекта** API не отдаёт — он задаётся в `projects.cfg`.
- **Перенесённые задачи** (номер другого проекта) и подзадачи без номера получают новые
  номера; старый номер ищется в Трекере по полю «Номер в YouGile».
- **Пользователи** переносятся по e-mail и требуют ручного маппинга на логины Трекера
  (`mapping/users.cfg`) на шаге импорта.
- **Ссылки на другие задачи** («Инфо / Лог» → «Ссылки на другие задачи») API не отдаёт —
  они не переносятся.
- **Стикеры** типов «Текст» и «Число» не переносятся.
- **Зеркала колонок** переносятся пустыми колонками: связи с исходной колонкой в API нет.
- **База знаний** (доска без колонок) и **отчёты** API не отдаёт — они не переносятся.
- **Точечные права** пользовательских ролей (отдельные доски, колонки, «мои» задачи) не переносятся: права очереди строятся по правам роли на все задачи.

## Безопасность

- Не выполняй разрушительных операций; экспортер работает только на чтение YouGile.
- Всегда проверяй результат на одном проекте до массового прогона.
- Ключ API и пароль не сохраняй в репозиторий.
