# YouGile Exporter

Утилита выгружает проекты, доски и задачи YouGile в файлы для универсального импортёра в Яндекс Трекер [yandex-tracker-importer](https://github.com/yandex/yandex-tracker-importer).

> **ИИ-агентам:** пошаговый runbook по проведению миграции — в [`AGENTS.md`](AGENTS.md).

## Быстрый старт

### 1. Соберите Docker/Podman образ

**Docker:**

```bash
docker build -t yougile-exporter:latest .
```

**Podman:**

```bash
podman build -t yougile-exporter:latest .
```

### 2. Подготовьте рабочую директорию

Рабочая директория должна содержать каталог `configs/` (подробнее — в разделе «Настройка»):

```
configs/
├── token.cfg      # ключ API компании YouGile
├── projects.cfg   # <префикс>:<название проекта>, по строке на проект
└── timezone.cfg   # необязательный: часовой пояс, например Europe/Moscow
```

### 3. Запустите экспортер

Экспортер работает в контейнере и использует примонтированную рабочую директорию `/work`. Команда запускается
из каталога, где лежит папка `configs`.

**Docker:**

```bash
docker run --rm \
  --user "$(id -u):$(id -g)" \
  -v "$(pwd)":/work \
  -w /work \
  yougile-exporter:latest
```

`--user` запускает экспорт от вашего пользователя, чтобы он мог писать в рабочую директорию.

**Podman:**

```bash
podman run --rm \
  --userns=keep-id \
  -v "$(pwd)":/work \
  -w /work \
  yougile-exporter:latest
```

### Запуск без контейнера

Нужен Python 3.12 или новее. `<каталог экспортёра>` — каталог с `requirements.txt` и папкой `exporter/`.
Команда запускается из рабочей директории с папкой `configs`:

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r <каталог экспортёра>/requirements.txt
PYTHONPATH=<каталог экспортёра> python -m exporter
```

### Результат

Экспорт пишет в рабочую директорию:
- `data` — данные для импорта, формат описан в [документации импортёра](https://github.com/yandex/yandex-tracker-importer/tree/main/docs);
- `logs` — журнал `export-<дата>.log` и список перенумерованных задач `renumbered-<дата>.csv`;
- `state/yougile_keys.cfg` — выданные ключи задач, нужен для повторной выгрузки.

## Настройка

Файлы настроек лежат в папке `configs`, кодировка — UTF-8:
- `token.cfg` — ключ API компании YouGile;
- `projects.cfg` — какие проекты выгружать, по одному в строке: `<префикс>:<название проекта>`, например `MKT:Маркетинг`. Префикс — начало номеров задач проекта (`MKT-12`), он станет ключом очереди. Название пишется точно как в YouGile;
- `timezone.cfg` (необязательный) — часовой пояс для дат со временем, например `Europe/Moscow`. По умолчанию — UTC.

Вместо `token.cfg` можно указать логин, пароль и компанию — экспорт возьмёт существующий ключ компании:
- `login.cfg` — логин в YouGile;
- `password.cfg` — пароль;
- `company.cfg` — точное название компании.

Если у компании нет ключа или компаний с таким названием несколько, укажите ключ в `token.cfg`.

### Как получить ключ API

Через API YouGile, например в интерактивной документации [ru.yougile.com/api-v2](https://ru.yougile.com/api-v2):
1. Узнайте ID компании: `POST /api-v2/auth/companies` с телом `{"login": "...", "password": "..."}` — нужно поле `id`.
2. Создайте ключ: `POST /api-v2/auth/keys` с телом `{"login": "...", "password": "...", "companyId": "..."}`.
3. Запишите значение `key` из ответа в `configs/token.cfg`.

## Проверки

Сначала экспорт проверяет настройки и проекты. Если что-то не так, он ничего не записывает, выводит список проблем и завершается с кодом 1. Проблемы такие:
- неизвестный часовой пояс; ключ API не найден или не подходит;
- нет `projects.cfg`, он пустой, в строке нет префикса или названия, префикс не из букв и цифр;
- префикс или проект повторяется в нескольких строках (регистр букв префикса не важен);
- проект не найден, не загрузился или несколько проектов называются одинаково;
- API не отдаёт список пользователей или задач компании;
- у проекта нет администратора или он недоступен — администратор станет владельцем очереди;
- колонки дают один и тот же статус: две колонки одной доски или колонки с разными названиями, из которых получается один ключ (например, «Этап 1» и «Этап 2»); в названии колонки нет букв;
- стикеры проекта дают один ключ поля или в названии стикера нет букв;
- в `data` лежит прошлая выгрузка, а её проекта нет в `projects.cfg` или нет файла `state/yougile_keys.cfg`.

Для каждого проекта экспорт печатает, сколько задач с каким префиксом стоит в его колонках, например `MKT — 12, WEB — 1`. Сверьте префикс в `projects.cfg` с самым частым.

Если во время выгрузки не удалось получить задачу, файл, подписчиков или данные пользователя, экспорт завершается с кодом 1 и перечисляет, чего не хватает. Подробности — в журнале. Запустите экспорт снова. Файл, удалённый в YouGile, остаётся в тексте ссылкой и ошибкой не считается.

## Повторная выгрузка

Экспорт можно запускать снова в тот же каталог — например, чтобы добавить проект или новые задачи. В `projects.cfg` каждый раз перечисляются все проекты переноса.
- Ключи задач берутся из `state/yougile_keys.cfg`, поэтому повторный импорт находит уже перенесённые задачи и не создаёт копий. Храните этот файл вместе с `data`.
- Уже перенесённые задачи повторный импорт не меняет: правки, сделанные в YouGile после импорта, не переносятся.
- Ключ, выданный однажды, другой задаче не достаётся.
- Задачи, которые удалили или перенесли в YouGile, убираются из `data`.
- Если задачу не удалось выгрузить, в `data` остаётся её прежняя версия.
- Если задачу перенесли в YouGile в другой проект, она получит ключ новой очереди, а экспорт об этом напишет. Задача под старым ключом останется в Трекере.

## Что как переносится

| YouGile | Яндекс Трекер |
| --- | --- |
| Проект | Очередь с ключом из `projects.cfg`. Ключ очереди в Трекере — латинские буквы; префикс с цифрами или кириллицей замените при импорте в сопоставлении очередей |
| Участники проекта и их роли | Владелец очереди — администратор проекта, команда — участники. Права очереди по ролям: наблюдатель — чтение; сотрудник — чтение, создание и изменение задач; администратор — ещё настройки очереди; пользовательская роль — по её правам на все задачи проекта: показ — чтение, добавление задач — создание, изменение задач — изменение, настройки проекта или досок — настройки очереди. Импорт снимает с очереди права группы «Все сотрудники», как закрыт проект в YouGile. Участник без почты прав не получает. |
| Доска | Доска с теми же колонками. Если доска в проекте одна, на неё попадают и новые задачи очереди, кроме задач с меткой «Архив»; если досок несколько, новые задачи добавляют на доску вручную |
| Колонка | Статус. Колонки, названия которых отличаются только регистром букв или лишними пробелами, становятся одним статусом |
| Задача | Задача. Чат — комментарии, чек-листы объединяются в один |
| Подзадача | Подзадача. Если у подзадачи нет своей колонки, она попадает в очередь, статус и на доску родителя: из проекта, с префикса которого начинается её номер, а если такого родителя нет — первого; при повторной выгрузке — из очереди её прежнего ключа. У задачи Трекера один родитель, с остальными родителями — простая связь |
| Выполненная задача | Задача со статусом своей колонки, без резолюции: отметка «выполнено» в YouGile не связана с колонкой |
| Архивная задача | Задача с меткой «Архив» и статусом своей колонки, не на доске |
| Исполнители | Первый — исполнитель, остальные и подписчики чата — наблюдатели |
| Стикер приоритета (с иконкой приоритета и значениями low, normal, major, critical) | Приоритет |
| Таймтрекинг | Оценка и затраченное время |
| Номер задачи | Ключ задачи; номер из YouGile — в поле «Номер в YouGile» (`yougileKey`) |
| Стикеры | Локальные поля очереди с одним значением; значение спринта — с датами, например `Sprint 1 (24.06–08.07)` |

### Номера задач

Ключ задачи в Трекере начинается с ключа очереди. Задача сохраняет свой номер, если он с префиксом проекта. Новый номер получают:
- задача, перенесённая из другого проекта: в YouGile у неё остаётся старый номер, например `WEB-3` в проекте MKT;
- подзадача, которая попала в очередь родителя из другого проекта;
- подзадача без номера проекта (`ID-17`);
- задача, чей номер прошлая выгрузка уже отдала другой задаче.

Новые номера идут после наибольшего номера с этим префиксом в компании, включая удалённые задачи. Старые и новые номера — в `logs/renumbered-<дата>.csv`. Найти задачу по старому номеру можно через поле «Номер в YouGile».

Если в одной очереди у двух задач одинаковый номер (у двух проектов YouGile один префикс), вторая не выгружается, а экспорт пишет о ней. Смените префикс одного из проектов в настройках YouGile — YouGile перенумерует его задачи.

### Даты и пользователи

Даты начала и дедлайна переносятся днями. Дата со временем считается в часовом поясе из `timezone.cfg`, дата без времени — тот же день, что в YouGile.

Пользователи выгружаются по почте из аккаунта YouGile; при импорте их нужно сопоставить с логинами Трекера. Пользователь без почты или удалённый из компании выгружается как `yougile-user-<id>` — его тоже нужно сопоставить.

## Ограничения

Из-за особенностей API YouGile:
1. API не отдаёт префикс проекта, поэтому его нужно указать в `projects.cfg`.
2. API не отдаёт ссылки на другие задачи («Инфо / Лог» → «Ссылки на другие задачи»), поэтому они не переносятся. Подзадачи переносятся.
3. Стикеры типов «Текст» и «Число» не переносятся.
4. Зеркало колонки API отдаёт пустой колонкой без связи с исходной: на доске оно переносится пустой колонкой, а его задачи стоят только в исходной колонке.
5. Доски базы знаний и статьи API не отдаёт: доска без колонок не переносится.
6. Отчёты и сводки API не отдаёт, они не переносятся.
7. Права пользовательской роли на отдельные доски, колонки и задачи, а также на задачи «мои», «со мной», «созданные мной» не переносятся: права очереди строятся по правам роли на все задачи проекта.
