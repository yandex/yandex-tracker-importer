# AGENTS.md — руководство для ИИ-агента: миграция Kaiten → Yandex Tracker

Ты помогаешь пользователю перенести доски **Kaiten** в **Yandex Tracker**. Этот
инструмент (`kaiten_exporter`) выгружает доски и карточки Kaiten в YAML,
совместимый с универсальным импортёром `trackin`. Полный конвейер:

```
Kaiten API  →  kaiten_exporter (этот проект)  →  data/*.yaml  →  trackin  →  Yandex Tracker
```

Экспортер **только читает** Kaiten и пишет файлы — ничего не меняет ни в Kaiten,
ни в Трекере. Заливкой в Трекер занимается отдельный импортёр `trackin`.

---

## Что спросить у пользователя

1. **Домен Kaiten** — `https://<домен>.kaiten.ru`.
2. **API-токен Kaiten** — Kaiten → аватар → *Настройки профиля → API-ключ*.
   Достаточно прав на чтение.
3. **Какие доски переносить** — можешь помочь выбрать (см. «Шаг 1»).
4. **Ключи очередей** в Трекере для каждой доски — короткие, латиницей (`PROD`,
   `SUPPORT`). Можешь предложить сам из названий досок.

> Токены — секреты: не выводи их в логи, не коммить в репозиторий, предупреди
> пользователя перевыпустить токен после миграции.

---

## Шаг 1. Discovery — помоги выбрать доски

С токеном перечисли пространства и доски, чтобы предложить выбор и ключи очередей:

```bash
curl -H "Authorization: Bearer <token>" https://<домен>.kaiten.ru/api/v1/spaces
curl -H "Authorization: Bearer <token>" https://<домен>.kaiten.ru/api/v1/spaces/<spaceId>/boards
```

Каждая доска — это `id` + `title`. Предложи пользователю строки вида
`<board_id>:<QUEUE_KEY>` (ключ — транслит названия, обрезанный до короткого).

## Шаг 2. Собери образ

```bash
docker build -t kaiten-exporter:latest .    # либо podman build …
```

## Шаг 3. Подготовь `configs/` и запусти

```
configs/
├── source_kaiten_url.cfg     # https://<домен>.kaiten.ru
├── source_kaiten_token.cfg   # API-токен
└── boards.cfg                # <board_id>:<QUEUE_KEY>, по строке на доску
```

```bash
docker run --rm -v "$(pwd)":/work -w /work kaiten-exporter:latest
```

**Совет:** начни с ОДНОЙ доски, проверь результат, потом добавь остальные в
`boards.cfg`. Результат — в `data/`, логи — в `logs/`.

## Шаг 4. Проверь выгрузку

- `data/queues/<KEY>/queue.yaml` — очередь, статусы, воркфлоу, локальные поля;
- `data/queues/<KEY>/<KEY>-N/issue.yaml` — задачи (рядом `attachments/`);
- `data/{statuses,issue_types,categories,global_fields}.yaml` — общие справочники.

Открой пару `issue.yaml` и убедись, что `summary`/`status`/`assignee`/`comments`
выглядят осмысленно.

## Шаг 5. Импорт в Tracker (через `trackin`)

Готовые `data/` заливает импортёр `trackin` (отдельный проект). Ключевой ручной
шаг — **сопоставление пользователей**: в выгрузке пользователи стоят по e-mail
Kaiten, при импорте их надо смапить на логины Трекера в `mapping/users.cfg`.
Дальнейшие детали — в документации `trackin`.

## Карта соответствий (кратко)

| Kaiten | Yandex Tracker |
|---|---|
| Доска (board) | Очередь + Проект |
| Колонка (column) | Статус |
| Карточка (card) | Задача |
| Тип карточки | Тип задачи |
| Ответственный / участники | `assignee` / `followers` |
| Чек-листы / комментарии / файлы | одноимённое |
| Списания времени | `worklogs` |
| Связи (parent/child, блокеры) | `links` (`is parent task for` / `depends on`) |
| Кастом-поля | Локальные поля очереди |
| Спринт | Тег |
| Дорожка (swimlane) | Глобальное поле `kaitenLane` (если на доске >1 дорожки) |

Полное описание полей и нюансов — в [`README.md`](README.md).

## Ограничения (проговори пользователю заранее)

- **Пользователи** переносятся по e-mail и требуют ручного маппинга на логины
  Трекера (`mapping/users.cfg`) на шаге импорта.
- **Связи** и **списания времени** в Kaiten — платные фичи; на бесплатном тарифе
  их в данных не будет.
- **Архивные** карточки по умолчанию не выгружаются.
- **Не переносятся:** автоматизации/триггеры, SLA/сервисы. Спринты — только как тег.
- Дата и автор создания задачи проставляются на шаге импорта, а не экспортёром.

## Безопасность

- Не выполняй разрушительных операций; экспортер работает только на чтение Kaiten.
- Всегда проверяй результат на одной доске до массового прогона.
- Токены не сохраняй в репозиторий; предложи перевыпустить их после миграции.
