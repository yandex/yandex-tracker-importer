# Экспортер из Kaiten в формат для универсального импортера в Yandex Tracker

Инструмент выгружает доски и карточки Kaiten в YAML-формат, совместимый с
универсальным импортером в Yandex Tracker. Описание форматов выходных файлов
см. в документации импортёра.

> **ИИ-агентам:** пошаговый runbook по проведению миграции — в [`AGENTS.md`](AGENTS.md).

## Быстрый старт

### 1. Соберите Docker/Podman образ

**Docker:**

```bash
docker build -t kaiten-exporter:latest .
```

**Podman:**

```bash
podman build -t kaiten-exporter:latest .
```

### 2. Подготовьте рабочую директорию

Рабочая директория должна содержать каталог `configs/` с настройками подключения:

```
configs/
├── source_kaiten_url.cfg     # адрес инстанса Kaiten, напр. https://acme.kaiten.ru
├── source_kaiten_token.cfg   # API-токен Kaiten (Bearer)
└── boards.cfg                # <board_id>:<QUEUE_KEY> по строке на доску
```

Каталоги `data/` (результат) и `logs/` создаются автоматически.

### 3. Запустите экспортер

Экспортер работает в контейнере и использует примонтированную рабочую директорию
`/work`. Команда запускается из каталога, где лежит папка `configs`.

**Docker:**

```bash
docker run --rm \
  -v "$(pwd)":/work \
  -w /work \
  kaiten-exporter:latest
```

**Podman:**

```bash
podman run --rm \
  --userns=keep-id \
  -v "$(pwd)":/work \
  -w /work \
  kaiten-exporter:latest
```

После выполнения результат появится в `data/`, логи — в `logs/`.
В конце экспорт выводит сводку: доски и карточки, которые не выгрузились, и файлы,
которые не скачались; при таких ошибках код завершения — 1. Файл, который не
скачался, импорт пропустит; если в `attachments/` осталась копия с прошлого запуска,
импорт загрузит её.

Скачивание файла повторяется при сетевых сбоях, ответах 408, 429 и 5xx и неполном
содержимом. Файл сохраняется, только если его размер совпал с размером в Kaiten и с
`Content-Length` несжатого ответа, когда они известны.

Если в сводке есть файлы, до импорта запустите экспорт повторно в тот же каталог:
файл, размер которого совпадает с размером в Kaiten, не скачивается заново; файл, размер
которого в Kaiten не указан, скачивается заново. Это верно, пока состав карточек на
досках не менялся (карточки не создавались, не удалялись и не переносились между
досками): номера задач зависят от состава карточек. Импорт не добавляет файлы к уже
созданным задачам.

## Получение API-токена Kaiten

1. Откройте профиль в Kaiten → **Настройки профиля** → **API-ключ**.
2. Сгенерируйте токен и вставьте его в `configs/source_kaiten_token.cfg`.
3. В `configs/source_kaiten_url.cfg` укажите адрес вашего инстанса
   (`https://<домен>.kaiten.ru`).

Токену достаточно прав на чтение пространств, досок, карточек, спринтов и итераций,
комментариев и вложений.

## Конфигурационные файлы

| Файл                     | Описание                                | Пример                                        |
| ------------------------ | --------------------------------------- | --------------------------------------------- |
| `boards.cfg`             | Доски для экспорта и ключи очередей.     | `1234:FIRSTQUEUE`<br>`5678:SECONDQUEUE`       |
| `source_kaiten_url.cfg`  | Адрес инстанса Kaiten.                   | `https://acme.kaiten.ru`                      |
| `source_kaiten_token.cfg`| API-токен Kaiten.                        | `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`        |

## Соответствие сущностей

| Kaiten                        | Yandex Tracker                                   |
| ----------------------------- | ------------------------------------------------ |
| Доска (board)                 | Очередь (`queue.yaml`) + проект (`project.yaml`) + доска (`boards.yaml`) |
| Колонка (column)              | Статус (`statuses.yaml`, шаги воркфлоу)          |
| Подколонка                    | Статус «Колонка / Подколонка»                    |
| Карточка (card)               | Задача (`issue.yaml`)                            |
| Тип карточки (card type)      | Тип задачи (`issue_types.yaml`)                  |
| Ответственный / участники     | `assignee` / `followers`                         |
| Комментарии                   | `comments`                                       |
| Чек-листы                     | `checklistItems` (один список; при нескольких чек-листах пункт начинается с названия чек-листа) |
| Файлы                         | `attachments` + файлы в `attachments/`; ссылки на них в описании и комментариях ведут на вложения задачи|
| Файлы по ссылкам (облака)     | Ссылки в конце `description`                     |
| Списания времени (time logs)  | `worklogs`                                        |
| Связи (родитель, блокер)      | `links`, и между досками выгрузки                |
| Активная блокировка           | Метка «Заблокировано в Kaiten», причина — комментарий «Заблокировано: …» от автора блокировки (если он неизвестен — от автора карточки) с её датой; снятые блокировки не переносятся |
| ASAP                          | Приоритет `critical`                             |
| Срок                          | `deadline`                                       |
| Плановые даты                 | `start` / `end`                                  |
| Метки (tags)                  | `tags`                                           |
| Спринт, итерация              | Спринт доски, `sprint` у задачи                  |
| Архивная карточка             | Задача с меткой «Архив Kaiten», не на доске      |
| Кастомные свойства            | Локальные поля очереди + `local_*` у задач       |

## Структура файлов после экспорта

```
data/
├── queues/
│   └── <QUEUE_KEY>/
│       ├── queue.yaml
│       └── <QUEUE_KEY>-<N>/
│           ├── issue.yaml
│           └── attachments/
│               ├── spec_55.pdf
│               └── image_56.png
├── projects/
│   └── <board_title>_<board_id>/
│       └── project.yaml
├── boards.yaml
├── statuses.yaml
├── resolutions.yaml
├── issue_types.yaml
└── categories.yaml
```

## Особенности работы

1. Пользователи выгружаются по e-mail. При импорте в Yandex Tracker каждого
   пользователя, который встречается в выгрузке, нужно сопоставить с логином через
   `mapping/users.cfg`, включая владельца API-токена Kaiten (он становится
   владельцем очередей и автором проектов) и системного пользователя
   `robot@kaiten.io`, если он есть в выгрузке.
2. Импорту нужны файлы сопоставлений `mapping/queues.cfg`, `mapping/statuses.cfg`,
   `mapping/issue_types.cfg` и `mapping/resolutions.cfg`. Строка в них нужна только
   для ключа, который в Трекере другой: ключи очередей — из `boards.cfg`, статусов и
   типов — из `statuses.yaml` и `issue_types.yaml`, резолюции — из `resolutions.yaml`.
3. Тип статуса берётся из типа колонки Kaiten: начальная колонка — начальный
   статус, колонка в работе — в процессе, завершающая — завершён. Подколонка получает
   тип своей колонки, колонка без типа — «в процессе». Колонка без
   названия становится статусом «Колонка <id>». Колонки с одинаковым названием
   (без учёта регистра и лишних пробелов) — один статус. Новая задача создаётся в
   статусе первой колонки доски, а если у неё есть подколонки — первой подколонки.
   Задача из завершающей колонки получает резолюцию «Решён» (`fixed`); дата решения —
   время последнего перемещения карточки в завершающую колонку, а если его нет — время
   завершения или последнего изменения карточки, но не раньше её создания; автор
   решения — последний редактор карточки, а если он неизвестен — её автор. Без автора
   и дат резолюция не ставится.
4. Названия статусов, типов задач и полей длиннее 50 символов обрезаются; если
   обрезанные названия совпадают, к ним добавляется « (2)», « (3)».
5. Доска Kaiten становится и доской Трекера: колонка доски содержит статусы своих
   подколонок. Статус может быть только в одной колонке доски Трекера: статус
   одноимённых колонок остаётся в первой из них, колонка без статусов не создаётся.
   WIP-лимит по числу карточек становится ограничением колонки, лимит по размеру
   карточек и лимиты подколонок не переносятся. На доску попадают задачи её
   очереди.
6. Спринты доски и итерации её пространств становятся спринтами доски Трекера.
   Итерация становится спринтом каждой выгружаемой доски, на которой есть её
   неархивные карточки. Статусы: активный спринт или итерация — в работе, завершённые —
   выпущены, архивный спринт — в архиве, остальные — черновики; удалённые итерации
   не переносятся. На доске Трекера в работе один спринт — начатый позже остальных,
   другие активные переносятся черновиками. Задача попадает в один спринт своей
   доски: активную итерацию, иначе запланированную, иначе спринт, иначе последнюю
   завершённую итерацию. Спринт или итерация без даты начала или конца, с
   нераспознанной датой либо с началом позже конца не переносится. Если ни один
   спринт задачи не переносится на её доску, известное название спринта становится
   меткой. Если итерации недоступны на тарифе, доски выгружаются без них.
7. Архивная карточка становится задачей с меткой «Архив Kaiten». Она не попадает на
   доску и в спринты, название её спринта становится меткой. Правило добавления доски
   исключает задачи с этой меткой; активная карточка с такой меткой тоже не попадёт на
   доску — экспорт предупреждает об этом. Это действует для досок и задач, которые
   создаёт импорт этой выгрузки: настройки уже перенесённых досок и задач повторный
   импорт не меняет.
8. Пользовательские свойства с одинаковым названием становятся разными полями:
   занятое название получает « (2)», « (3)» в порядке идентификаторов свойств.
9. Каждая доска из `boards.cfg` экспортируется вместе со всеми её карточками.
   Выгружайте в пустой каталог `data/`: файлы прежних выгрузок не удаляются. Исключение —
   повторный запуск, чтобы докачать файлы (см. выше).
10. Срок и плановые даты переносятся днями в часовом поясе таймлайна компании Kaiten
   (настройки компании); дата без времени — днём, указанным в Kaiten. Если пояс
   получить не удалось, дни берутся по UTC.
11. Ключи задач формируются как `<QUEUE_KEY>-<N>`, где `N` — порядковый номер
   карточки по дате создания; карточки без даты создания идут последними.
12. Связи «родитель — подзадача» и активные блокеры переносятся и между карточками
   разных досок из `boards.cfg`. Связь с карточкой доски, которой нет в `boards.cfg`
   или которая не загрузилась из Kaiten, не переносится. Импорт создаёт связь вместе с
   задачей, в которой она записана: если задача создана, а задача на другом конце
   связи — нет, повторный импорт эту связь не создаёт.
