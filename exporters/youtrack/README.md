# Экспортер из YouTrack в формат для универсального импортера в Yandex Tracker

Инструмент выгружает проекты и задачи YouTrack в YAML-формат импортера
[yandex-tracker-importer](https://github.com/yandex/yandex-tracker-importer). Форматы выходных файлов
описаны в [документации импортера](https://github.com/yandex/yandex-tracker-importer/tree/main/docs).

> **ИИ-агентам:** пошаговый runbook по проведению миграции — в [`AGENTS.md`](AGENTS.md).

## Быстрый старт

### 1. Соберите Docker/Podman образ

**Docker:**

```bash
docker build -t youtrack-exporter:latest .
```

**Podman:**

```bash
podman build -t youtrack-exporter:latest .
```

### 2. Подготовьте рабочую директорию

Рабочая директория должна содержать каталог `configs/`:

```
configs/
├── source_youtrack_url.cfg     # адрес YouTrack
├── source_youtrack_token.cfg   # постоянный токен YouTrack
├── projects.cfg                # <ключ проекта>:<QUEUE_KEY>, по строке на проект
├── users.cfg                   # необязательный: <логин>:<e-mail>
└── restricted_component.cfg    # необязательный: название компонента задач с ограниченной видимостью
```

Каталоги `data/` (результат) и `logs/` создаются автоматически.

### 3. Запустите экспортер

Экспортер работает в контейнере и использует примонтированную рабочую директорию `/work`.
Команда запускается из каталога, где лежит папка `configs`.

**Docker:**

```bash
docker run --rm \
  -v "$(pwd)":/work \
  -w /work \
  youtrack-exporter:latest
```

**Podman:**

```bash
podman run --rm \
  --userns=keep-id \
  -v "$(pwd)":/work \
  -w /work \
  youtrack-exporter:latest
```

Результат появится в `data/`, журнал — в `logs/`.

### 4. Проверьте сводку

В конце экспорт печатает сводку ошибок. Если ошибки есть, код завершения — 1. В сводку попадают:

- проекты и задачи, которые не выгрузились;
- задачи, у которых не загрузились комментарии, файлы или учёт времени;
- файлы, которые не скачались;
- пользователи без e-mail (см. «Пользователи»);
- список пользователей, роли или доски, которые не загрузились.

Файл, который не скачался, импорт пропустит. Чтобы докачать файлы, до импорта запустите экспорт ещё раз в
тот же каталог. Файл, размер которого совпадает с размером в YouTrack, заново не скачивается.

## Адрес и токен YouTrack

**Адрес** — то, что открывается в браузере до `/issues`, `/agiles` и т. п.:

- YouTrack Cloud: `https://example.youtrack.cloud`;
- YouTrack Server или Cloud на старом домене: `https://example.com/youtrack`, `https://example.myjetbrains.com/youtrack`.

**Постоянный токен:**

1. Откройте профиль: аватар → **Profile** (**Профиль**).
2. Перейдите на вкладку **Account Security** (**Безопасность учётной записи**).
3. В разделе **Tokens** нажмите **New token…**.
4. В **Scope** отметьте **YouTrack** и **YouTrack Administration**.
5. Нажмите **Create token** и скопируйте токен: он показывается один раз.

Токен выпускает администратор YouTrack. Без прав администратора API не отдаёт настройки проектов.

## Конфигурационные файлы

| Файл                        | Описание                                              | Пример                                   |
| --------------------------- | ----------------------------------------------------- | ---------------------------------------- |
| `source_youtrack_url.cfg`   | Адрес YouTrack.                                       | `https://example.youtrack.cloud`         |
| `source_youtrack_token.cfg` | Постоянный токен.                                     | `perm-…`                                 |
| `projects.cfg`              | Проекты для экспорта и ключи очередей. Ключ очереди — один на проект. | `WH:WAREHOUSE`<br>`SUP:SUPPORT` |
| `users.cfg`                 | E-mail пользователей, у которых его нет в YouTrack.   | `anna:anna@example.com`                  |
| `restricted_component.cfg`  | Название компонента задач, видимых части пользователей. По умолчанию — «Ограниченная видимость». | `Закрытые задачи` |

Проект в `projects.cfg` задаётся ключом (префикс номеров задач, `WH` в `WH-12`) или id. Список проектов:

```bash
curl -H "Authorization: Bearer <токен>" \
  "https://example.youtrack.cloud/api/admin/projects?fields=id,shortName,name,archived&\$top=1000"
```

## Пользователи

Пользователи выгружаются по e-mail. При импорте каждого пользователя из выгрузки нужно сопоставить
с логином Трекера в `mapping/users.cfg` импортера.

Если у пользователя нет e-mail в YouTrack:

- автором становится владелец токена;
- комментарий и запись учёта времени начинаются со строки «Автор: <имя>»;
- логин пользователя попадает в сводку ошибок.

Чтобы сохранить автора, добавьте его e-mail в `configs/users.cfg` и запустите экспорт ещё раз:

```
anna:anna@example.com
```

## Видимость

- **Комментарий, видимый части пользователей,** в Трекере виден всем, у кого есть доступ к задаче: Трекер не
  ограничивает видимость комментариев.
- **Задача, видимая части пользователей,** получает компонент из `configs/restricted_component.cfg`, по
  умолчанию «Ограниченная видимость». Если в проекте есть такие задачи, а среди значений Subsystem есть
  значение с названием компонента, проект попадает в сводку ошибок: задайте в файле другое название. Задачи с
  компонентом читают и изменяют автор, исполнитель, пользователи поля «Доступ» и владелец очереди. В поле «Доступ» —
  пользователи и участники групп, которым задача видна в YouTrack, на момент экспорта, кроме
  заблокированных.
  - Сопоставьте в `mapping/users.cfg` импортера всех пользователей поля «Доступ»: задача с несопоставленным
    пользователем не импортируется.
  - Права компонента импорт ставит в конце прогона. Задачу с этим компонентом, не созданную первым прогоном,
    повторный импорт создаёт, если учётная запись импорта — владелец очереди.

## Повторный экспорт

Выгружайте в пустой каталог `data/`: файлы прежних выгрузок не удаляются. Исключение — повторный запуск до
импорта, чтобы докачать файлы или добавить e-mail пользователей. Импорт не меняет поля уже созданных задач.

Связи между задачами разных проектов переносятся, только если оба проекта в одной выгрузке.

## Приватные поля

Поле проекта YouTrack может быть приватным: его значения видят только роли с правом Read Issue Private Fields.
В Трекере такое поле становится обычным локальным полем очереди, и его значения видят все, у кого есть доступ к
задаче.

## Ограничения API YouTrack

- **Архивный проект.** API не отдаёт задачи архивного проекта, а связи с ними пропадают у задач других
  проектов. Восстановите проект из архива перед экспортом. Архивный проект из `projects.cfg` попадает в
  сводку ошибок.
