# AGENTS.md — руководство для ИИ-агента: миграция YouTrack → Yandex Tracker

Ты помогаешь пользователю перенести проекты **YouTrack** в **Yandex Tracker**. Этот инструмент
(`youtrack-exporter`) выгружает проекты и задачи YouTrack в YAML для импортера
[yandex-tracker-importer](https://github.com/yandex/yandex-tracker-importer). Полный конвейер:

```
YouTrack REST API  →  youtrack-exporter (этот проект)  →  data/*.yaml  →  yandex-tracker-importer  →  Yandex Tracker
```

Экспортер **только читает** YouTrack и пишет файлы. Заливкой в Трекер занимается импортер — его runbook:
[AGENTS.md импортера](https://github.com/yandex/yandex-tracker-importer/blob/main/AGENTS.md).

---

## Что спросить у пользователя

1. **Адрес YouTrack** — например, `https://example.youtrack.cloud` или `https://example.com/youtrack`.
2. **Постоянный токен администратора** с областями *YouTrack* и *YouTrack Administration* — профиль →
   *Account Security → Tokens → New token*.
3. **Какие проекты переносить** — список проектов см. в «Шаг 1».
4. **Ключи очередей** в Трекере для каждого проекта — короткие, латиницей (`WAREHOUSE`, `SUPPORT`).
   Предложи ключи из ключей проектов YouTrack.
5. **Архивные проекты** — их нужно восстановить из архива в YouTrack до экспорта.

> Токены — секреты: не выводи их в логи, не коммить в репозиторий, предложи пользователю удалить
> токен в YouTrack после миграции.

## Шаг 1. Помоги выбрать проекты

```bash
curl -H "Authorization: Bearer <token>" \
  "<адрес>/api/admin/projects?fields=id,shortName,name,archived&\$top=1000"
```

Каждый проект — это `shortName` (ключ) + `name`. Предложи пользователю строки вида
`<shortName>:<QUEUE_KEY>`. Проект с `archived: true` попроси восстановить из архива.

## Шаг 2. Собери образ

```bash
docker build -t youtrack-exporter:latest .    # либо podman build …
```

## Шаг 3. Подготовь `configs/` и запусти

```
configs/
├── source_youtrack_url.cfg     # адрес YouTrack
├── source_youtrack_token.cfg   # постоянный токен
├── projects.cfg                # <ключ проекта>:<QUEUE_KEY>, по строке на проект
├── users.cfg                   # необязательный: <логин>:<e-mail>
└── restricted_component.cfg    # необязательный: название компонента задач с ограниченной видимостью
```

```bash
docker run --rm -v "$(pwd)":/work -w /work youtrack-exporter:latest
```

Сначала выгрузи один проект и проверь результат. Итоговую выгрузку всех проектов делай в пустой
`data/`: связи между задачами разных проектов переносятся только внутри одной выгрузки.

## Шаг 4. Разбери сводку

В конце экспорт печатает сводку ошибок; при ошибках код завершения — 1. Исправляй ошибки до импорта:
импорт не меняет поля уже созданных задач.

- `Project <ключ>: Project <ключ> is archived …` — попроси пользователя восстановить проект из архива и
  запусти экспорт заново в пустой `data/`.
- `Project <ключ>: Component … is a Subsystem value …` — название компонента задач с ограниченной видимостью
  совпадает со значением поля Subsystem («Подсистема»). Спроси у пользователя другое название, запиши его в
  `configs/restricted_component.cfg` и запусти экспорт заново.
- `Project <ключ>: Project <ключ> is not found` — проверь ключ в `projects.cfg` и права владельца токена.
- `<KEY>-<N>, file <имя>: <ошибка>` — файл не скачался. Запусти экспорт повторно в тот же каталог, файлы
  докачаются.
- `<KEY>-<N>, comments|files|work items: … are not loaded` — данные задачи не загрузились. Запусти экспорт
  повторно.
- `YouTrack: users are not loaded`, `roles are not loaded …`, `boards are not loaded`, `board <название> is not
  loaded` — не загрузились пользователи, роли или доски. Проверь, что токен выпущен администратором, и запусти
  экспорт повторно.
- `User <логин> has no e-mail …` — спроси у пользователя e-mail, добавь строку `<логин>:<e-mail>` в
  `configs/users.cfg` и запусти экспорт повторно.

## Шаг 5. Проверь выгрузку

- `data/queues/<KEY>/queue.yaml` — очередь, рабочий процесс, компоненты, версии, локальные поля, права;
- `data/queues/<KEY>/<KEY>-N/issue.yaml` — задачи (рядом `attachments/`);
- `data/{statuses,resolutions,issue_types,boards}.yaml` — общие справочники и доски.

Открой пару `issue.yaml` и убедись, что `summary`, `status`, `assignee`, `comments` выглядят осмысленно.

## Шаг 6. Импорт в Трекер

Импортеру нужны файлы сопоставлений в `mapping/`:

- `users.cfg` — e-mail → логин Трекера для каждого пользователя из выгрузки;
- `groups.cfg` — группы из прав очередей, если в Трекере они называются иначе, в том числе «Все сотрудники»;
- `queues.cfg` — ключи очередей из `projects.cfg`;
- `statuses.cfg`, `issue_types.cfg` — ключи из `data/statuses.yaml` и `data/issue_types.yaml`;
- `resolutions.cfg` — ключи из `data/resolutions.yaml`.

Формат строки — `<ключ в выгрузке>:<ключ в Трекере>`. Строка нужна только для ключа, который в Трекере
другой; сами файлы обязательны.

Статусы ищутся в Трекере по ключу, затем по названию. Если в организации уже есть статус с тем же ключом
или названием, но другого типа, сопоставь его в `statuses.cfg` с подходящим статусом.

## Карта соответствий (кратко)

| YouTrack | Yandex Tracker |
|---|---|
| Проект | Очередь |
| Команда проекта | Участники очереди |
| Роли в проекте | Права очереди |
| State / Type / Priority | Статус / тип задачи / приоритет |
| Решённое состояние | Статус и резолюция |
| Subsystem, версии | Компоненты, версии |
| Остальные поля | Локальные поля очереди |
| Связи, подзадачи | `links` |
| Комментарии, файлы, учёт времени | `comments`, `attachments`, `worklogs` |
| Agile-доска, спринты | Доска очереди, спринты |

Подробности — в [`README.md`](README.md) и [`docs/objects/`](docs/objects/).

## Ограничения (проговори пользователю заранее)

- **Архивные проекты** выгружаются только после восстановления из архива.
- **Комментарии, видимые части пользователей,** в Трекере видны всем с доступом к задаче: Трекер не
  ограничивает видимость комментариев.
- **Задачи, видимые части пользователей,** закрыты компонентом «Ограниченная видимость»: в поле «Доступ» —
  пользователи и участники групп, которым задача видна, на момент экспорта, кроме заблокированных. Сопоставь их всех в
  `mapping/users.cfg`: задача с несопоставленным пользователем не импортируется. Запускай импорт от
  владельца очереди: только тогда повторный прогон создаёт такие задачи, не созданные первым.
- **Приватные поля** проекта в Трекере видны всем, у кого есть доступ к задаче.
- **Пользователи без e-mail** в авторах заменяются владельцем токена, в поле «Доступ» не попадают — их e-mail
  нужен в `configs/users.cfg`, затем повторный экспорт.

## Безопасность

- Экспортер работает только на чтение YouTrack.
- Проверяй результат на одном проекте до полного прогона.
- Токен не сохраняй в репозиторий.
