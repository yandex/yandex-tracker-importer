# Экспортер из WEEEK в формат для универсального импортера в Yandex Tracker

Инструмент выгружает проекты и задачи WEEEK в YAML-формат импортера
[yandex-tracker-importer](https://github.com/yandex/yandex-tracker-importer). Форматы выходных файлов
описаны в [документации импортера](https://github.com/yandex/yandex-tracker-importer/tree/main/docs).

> **ИИ-агентам:** пошаговый runbook по проведению миграции — в [`AGENTS.md`](AGENTS.md).

## Быстрый старт

### 1. Соберите Docker/Podman образ

**Docker:**

```bash
docker build -t weeek-exporter:latest .
```

**Podman:**

```bash
podman build -t weeek-exporter:latest .
```

### 2. Подготовьте рабочую директорию

Рабочая директория должна содержать каталог `configs/`:

```
configs/
├── source_weeek_token.cfg   # API-токен WEEEK
├── projects.cfg             # <id проекта>:<QUEUE_KEY>, по строке на проект
└── users.cfg                # необязательный: <id пользователя>:<e-mail>
```

Каталоги `data/` (результат) и `logs/` создаются автоматически.

### 3. Запустите экспортер

Экспортер работает в контейнере и использует примонтированную рабочую директорию `/work`.
Команда запускается из каталога, где лежит папка `configs`.

**Docker:**

```bash
docker run --rm \
  -v "$(pwd)":/work \
  -w /work \
  weeek-exporter:latest
```

**Podman:**

```bash
podman run --rm \
  --userns=keep-id \
  -v "$(pwd)":/work \
  -w /work \
  weeek-exporter:latest
```

Результат появится в `data/`, журнал — в `logs/`.

### 4. Проверьте сводку

В конце экспорт печатает сводку ошибок. Если ошибки есть, код завершения — 1. В сводку попадают:

- метки, портфели и контакты CRM, которые не загрузились;
- проекты и задачи, которые не выгрузились;
- задачи, у которых не загрузились комментарии;
- файлы, которые не скачались;
- пользователи, которых нет среди участников пространства (см. «Исключённые участники»).

Файл, который не скачался, импорт пропустит. Чтобы докачать файлы, до импорта запустите экспорт ещё раз в
тот же каталог. Файл, размер которого совпадает с размером в WEEEK, заново не скачивается. Импорт не
добавляет файлы к уже созданным задачам.

## Получение API-токена WEEEK

1. Откройте WEEEK → название пространства → **Настройки** → **API**.
2. Нажмите **Добавить токен**, укажите название и создайте токен.
3. Вставьте токен в `configs/source_weeek_token.cfg`.

Запросы с токеном выполняются от имени его создателя.

## Конфигурационные файлы

| Файл                     | Описание                                         | Пример                         |
| ------------------------ | ------------------------------------------------ | ------------------------------ |
| `source_weeek_token.cfg` | API-токен WEEEK.                                  | `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx` |
| `projects.cfg`           | Проекты для экспорта и ключи очередей. Ключ очереди — один на проект. | `12:PAYMENTS`<br>`15:SUPPORT`  |
| `users.cfg`              | E-mail участников, исключённых из пространства.   | `a1b2c3d4-…:anna@example.com`  |

Id проекта — поле `id` в списке проектов API WEEEK:

```bash
curl -H "Authorization: Bearer <токен>" https://api.weeek.net/public/v1/tm/projects
```

## Соответствие сущностей

| WEEEK                              | Yandex Tracker                                         |
| ---------------------------------- | ------------------------------------------------------ |
| Портфель                           | Портфель (`portfolio.yaml`), вложенность сохраняется   |
| Проект                             | Очередь (`queue.yaml`) + проект (`project.yaml`)       |
| Доступ к приватному проекту        | Права очереди и проекта                                |
| Доска                              | Доска очереди (`boards.yaml`)                          |
| Колонка доски                      | Статус (`statuses.yaml`)                               |
| Задача                             | Задача (`issue.yaml`)                                  |
| Тип: задача / встреча / звонок     | Тип задачи `task` / `meeting` / `call`                 |
| Приоритет: низкий / средний / высокий | `minor` / `normal` / `critical`                     |
| Приоритет Hold                     | Приоритет `normal` и метка `Hold`                      |
| Завершённая задача                 | Резолюция «Решён» (`fixed`)                            |
| Исполнители                        | Первый — `assignee`, остальные — `followers`           |
| Наблюдатели                        | `followers`                                            |
| Подзадачи                          | Связь «родительская задача — подзадача»                |
| Метки                              | `tags`                                                 |
| Дата начала, срок                  | `start`, `deadline`                                    |
| Оценка времени                     | `originalEstimation`                                   |
| Пользовательские поля              | Локальные поля очереди                                 |
| Описание                           | `description` в markdown                               |
| Комментарии                        | `comments`                                             |
| Файлы                              | `attachments`; облачные файлы — ссылками в описании    |
| Учёт времени                       | `worklogs`                                             |

Подробности — в [`docs/objects/projects.md`](docs/objects/projects.md) и

## Пользователи

Пользователи выгружаются по e-mail. При импорте каждого пользователя из выгрузки нужно сопоставить
с логином Трекера в `mapping/users.cfg` импортера. Владелец токена WEEEK тоже попадает в выгрузку: он
становится руководителем очередей и автором проектов и портфелей.

### Исключённые участники

WEEEK не отдаёт e-mail участника, которого исключили из пространства. Его задачи, комментарии, файлы и
учёт времени остаются, но автор в них известен только по id.

Что делает экспорт:

- автором становится владелец токена;
- комментарий и запись учёта времени начинаются со строки «Автор в WEEEK: исключённый участник»;
- id пользователя попадает в сводку ошибок.

Чтобы сохранить автора, до импорта добавьте его e-mail в `configs/users.cfg` и запустите экспорт ещё раз:

```
a1b2c3d4-0000-0000-0000-000000000000:anna@example.com
```

## Приватные проекты и портфели

Доступ к приватному проекту получают только его участники и владелец токена:

- в очереди — чтение, создание и изменение задач;
- в проекте — чтение и изменение.

Команда, добавленная в доступ к проекту, переносится своими участниками: API WEEEK отдаёт участников
команды, но не саму команду. Проект, открытый всему пространству, переносится с доступом по умолчанию.

Приватный портфель доступен только владельцу токена: чтение и изменение. API WEEEK не отдаёт участников
портфеля. Остальным пользователям выдайте доступ в Трекере вручную.

До импорта сопоставьте в `mapping/users.cfg` импортера всех участников приватных проектов.

Если в журнале импорта есть `Error updating permissions`, права не применились, и очередь, проект или
портфель доступны всем. Исправьте сопоставление пользователей и задайте права в Трекере вручную.

## Архивные проекты

WEEEK не отдаёт задачи и доски архивного проекта. Восстановите проект из архива перед экспортом.
Архивный проект из `projects.cfg` попадает в сводку ошибок.

## Повторный экспорт

Выгружайте в пустой каталог `data/`: файлы прежних выгрузок не удаляются. Исключение — повторный запуск до
импорта, чтобы докачать файлы или добавить e-mail исключённых участников. Импорт не меняет уже созданные
задачи.

Ключи задач — `<QUEUE_KEY>-<N>`, где `N` — номер задачи по дате создания. Номера зависят от состава
задач. Выгружайте в пустой каталог и импортируйте в новые очереди, если:

- задачи создавались, удалялись или переносились между проектами;
- в прошлой выгрузке были ошибки проектов: задачи нескольких проектов распределяются только по
  выгруженным проектам.

## Ограничения API WEEEK

- **Связи задач** («блокирует», «ожидает», «связана») видны в интерфейсе WEEEK, но API их не отдаёт.
  После переноса восстановите их вручную.
- **Файл комментария** API отдаёт среди файлов задачи, без связи с комментарием. Экспорт относит файл к
  комментарию по автору и времени (см. [`docs/objects/tasks.md`](docs/objects/tasks.md)).
- **Кто завершил задачу**, API WEEEK не отдаёт. Автор решения — первый исполнитель с известным e-mail.
  Если таких исполнителей нет — автор задачи.
