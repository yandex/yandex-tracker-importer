# AGENTS.md — руководство для ИИ-агента: миграция WEEEK → Yandex Tracker

Ты помогаешь пользователю перенести проекты **WEEEK** в **Yandex Tracker**. Этот инструмент
(`weeek-exporter`) выгружает проекты и задачи WEEEK в YAML для импортера
[yandex-tracker-importer](https://github.com/yandex/yandex-tracker-importer). Полный конвейер:

```
WEEEK API  →  weeek-exporter (этот проект)  →  data/*.yaml  →  yandex-tracker-importer  →  Yandex Tracker
```

Экспортер **только читает** WEEEK и пишет файлы. Заливкой в Трекер занимается импортер — его runbook:
[AGENTS.md импортера](https://github.com/yandex/yandex-tracker-importer/blob/main/AGENTS.md).

---

## Что спросить у пользователя

1. **API-токен WEEEK** — WEEEK → название пространства → *Настройки → API → Добавить токен*.
2. **Какие проекты переносить** — список проектов см. в «Шаг 1».
3. **Ключи очередей** в Трекере для каждого проекта — короткие, латиницей (`PAYMENTS`, `SUPPORT`).
   Предложи ключи из названий проектов.
4. **Архивные проекты** — их нужно восстановить из архива в WEEEK до экспорта.

> Токены — секреты: не выводи их в логи, не коммить в репозиторий, предложи пользователю удалить
> токен в WEEEK после миграции.

---

## Шаг 1. Помоги выбрать проекты

```bash
curl -H "Authorization: Bearer <token>" https://api.weeek.net/public/v1/tm/projects
```

Каждый проект — это `id` + `name`. Предложи пользователю строки вида `<id>:<QUEUE_KEY>`.

## Шаг 2. Собери образ

```bash
docker build -t weeek-exporter:latest .    # либо podman build …
```

## Шаг 3. Подготовь `configs/` и запусти

```
configs/
├── source_weeek_token.cfg   # API-токен
├── projects.cfg             # <id проекта>:<QUEUE_KEY>, по строке на проект
└── users.cfg                # необязательный: <id пользователя>:<e-mail>
```

```bash
docker run --rm -v "$(pwd)":/work -w /work weeek-exporter:latest
```

**Совет:** начни с ОДНОГО проекта и проверь результат. Итоговую выгрузку всех проектов делай в пустой
`data/`: подзадачи и задачи нескольких проектов связываются только внутри одной выгрузки.

## Шаг 4. Разбери сводку

В конце экспорт печатает сводку ошибок; при ошибках код завершения — 1. Исправляй ошибки до импорта:
импорт не меняет уже созданные задачи.

- `Project <id>: Project <id> is archived …` — попроси пользователя восстановить проект из архива и запусти
  экспорт заново.
- `<KEY>-<N>, file <имя>: <ошибка>` — файл не скачался. Запусти экспорт повторно в тот же каталог, файлы
  докачаются. Это верно, пока состав задач не менялся и все проекты загрузились. Ошибка `Resource not found`
  означает, что файла больше нет в WEEEK.
- `Project <id>: …` с другой ошибкой — исправь причину, очисти `data/` и выгрузи все проекты заново: номера
  задач зависят от того, какие проекты загрузились.
- `<KEY>-<N>, comments: comments are not loaded` — комментарии задачи не загрузились. Запусти экспорт
  повторно.
- `Workspace: … are not loaded` — не загрузились метки, портфели или контакты CRM. Запусти экспорт повторно.
- `Workspace: portfolio … is not found` — портфеля проекта нет в списке портфелей. Проверь доступ владельца
  токена к портфелю.
- `User <id> is not a member of the workspace …` — участник исключён из пространства. Спроси у пользователя
  его e-mail, добавь строку `<id>:<e-mail>` в `configs/users.cfg` и запусти экспорт повторно.

## Шаг 5. Проверь выгрузку

- `data/queues/<KEY>/queue.yaml` — очередь, статусы, рабочий процесс, локальные поля;
- `data/queues/<KEY>/<KEY>-N/issue.yaml` — задачи (рядом `attachments/`);
- `data/projects/`, `data/portfolios/` — проекты и портфели;
- `data/{statuses,resolutions,issue_types,boards}.yaml` — общие справочники и доски.

Открой пару `issue.yaml` и убедись, что `summary`, `status`, `assignee`, `comments` выглядят осмысленно.

## Шаг 6. Импорт в Трекер

Импортеру нужны файлы сопоставлений в `mapping/`:

- `users.cfg` — e-mail → логин Трекера для каждого пользователя из выгрузки, включая владельца токена WEEEK
  и участников приватных проектов;
- `queues.cfg` — ключи очередей из `projects.cfg`;
- `statuses.cfg`, `issue_types.cfg` — ключи из `data/statuses.yaml` и `data/issue_types.yaml`;
- `resolutions.cfg` — ключи из `data/resolutions.yaml`.

Формат строки — `<ключ в выгрузке>:<ключ в Трекере>`. Строка нужна только для ключа, который в Трекере
другой; сами файлы обязательны.

## Карта соответствий (кратко)

| WEEEK | Yandex Tracker |
|---|---|
| Портфель | Портфель |
| Проект | Очередь + проект |
| Доска / колонка | Доска очереди / статус |
| Задача | Задача (`task`, `meeting`, `call`) |
| Завершённая задача | Резолюция «Решён» |
| Подзадачи | Связь «родительская задача — подзадача» |
| Пользовательские поля | Локальные поля очереди |
| Комментарии, файлы, учёт времени | `comments`, `attachments`, `worklogs` |

Подробности — в [`README.md`](README.md) и [`docs/objects/`](docs/objects/).

## Ограничения (проговори пользователю заранее)

- **Связи задач** («блокирует», «ожидает», «связана») API WEEEK не отдаёт — их нужно восстановить вручную.
- **Архивные проекты** выгружаются только после восстановления из архива.
- **Исключённые участники** известны только по id — их e-mail нужен в `configs/users.cfg`.
- **Команды** WEEEK не переносятся группами: API отдаёт только участников команд. Доступ к приватному
  проекту получают его участники по отдельности.

## Безопасность

- Экспортер работает только на чтение WEEEK.
- Проверяй результат на одном проекте до полного прогона.
- Токен не сохраняй в репозиторий.
