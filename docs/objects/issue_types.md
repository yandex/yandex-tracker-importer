# Типы задач

**Файл для импорта:** `issue_types.yaml`  
**Расположение:** `./data/issue_types.yaml`

> Примечание: Поля, отмеченные звёздочкой (<span style="color: red;">*</span>), являются обязательными.

## Общие сведения

| Поле                                     | Тип    | Описание                            |
|------------------------------------------|--------|-------------------------------------|
| `key`<span style="color: red;">*</span>  | Строка | Уникальный ключ типа задачи         |
| `name`<span style="color: red;">*</span> | Объект | Название типа задачи на двух языках |
| `description`                            | Строка | Описание типа задачи                |

---

## Пример `issue_types.yaml`

```yaml
- name: 
    en: Study
    ru: Исследование
  key: study
  description: Search for patterns
- name:
    ru: Командировка
    en: Business trip
  key: businessTrip
```


## Особенности работы

Тип задачи ищется в целевой организации по ключу. Если по ключу его нет, а в `mapping/issue_types.cfg` нет строки для этого ключа, импорт ищет тип с тем же названием на русском или на английском и использует его: создать тип с занятым названием нельзя. В журнале появляется `Issue Type … is mapped to the existing … by the same name`. Названия типов задач сравниваются на каждом языке отдельно и точно. Если название совпадает с названиями нескольких объектов, сопоставление нужно указать в `mapping/issue_types.cfg`.

Если несколько типов выгрузки сопоставлены с одним типом, у очереди остаётся воркфлоу первого из них, а резолюции объединяются. Если воркфлоу у них разные, в журнале — ошибка `Issue type … of queue … is mapped to … configured by an earlier entry, its workflow … is not used`. Задачи остальных типов в статусах, которых нет в оставшемся воркфлоу, не импортируются: чтобы их перенести, сопоставьте такие типы с разными типами в `mapping/issue_types.cfg`.
