# Очереди

**Файл для импорта:** `queue.yaml`  
**Расположение:** `./data/queues/<queue_key>/queue.yaml`

> Примечание: Поля, отмеченные звёздочкой (<span style="color: red;">*</span>), являются обязательными.

## Структура `workflows`

```yaml
- key: W1
  name: Рабочий процесс
  initialAction:
    name:
      en: Undefined
      ru: Не задано
    target: new
  steps:
    - status: new
      actions:
        - key: start
          name:
            en: Back to work
            ru: В работу
          target: inProgress
          conditions:
            - type: UserInGroupCondition
              group: Поддержка
          screen:
            title:
              en: Start
              ru: Начать
            commentRequired: true
            elements:
              - field: assignee
                required: true
          postFunctions:
            - type: AddCurrentUserToFieldFunction
              target: assignee
    - status: inProgress
      actions:
        - key: close
          name:
            en: Close
            ru: Закрыть
          target: closed
      afterCommentCreated:
        - type: TransitionCommentFunction
          actionId: close
          onAssigneeCommentOnly: true
```

| Поле                                              | Тип    | Описание                                                                                       |
|---------------------------------------------------|--------|------------------------------------------------------------------------------------------------|
| `key`<span style="color: red;">*</span>           | Строка | Идентификатор рабочего процесса                                                                |
| `name`<span style="color: red;">*</span>          | Строка | Название рабочего процесса                                                                     |
| `initialAction`<span style="color: red;">*</span> | Объект | Начальное действие рабочего процесса                                                           |
| `steps`<span style="color: red;">*</span>         | Массив | Шаги рабочего процесса (если в статус можно попасть из любого статуса, используйте metaAction) |

У шага, кроме `status`, `actions` и `metaAction`, может быть `afterCommentCreated` — функции после
комментария, например переход по комментарию (`TransitionCommentFunction`, переход указывается в
`actionId` по его `key`).

У перехода (`actions`, `metaAction`, `initialAction`):

| Поле            | Тип             | Описание                                                       |
|-----------------|-----------------|----------------------------------------------------------------|
| `name`          | Объект          | Название перехода на двух языках                               |
| `target`        | Строка          | Ключ целевого статуса                                          |
| `key`           | Строка          | Идентификатор перехода                                         |
| `conditions`    | Массив объектов | Условия перехода                                               |
| `screen`        | Объект          | Экран перехода: `title`, `comment`, `commentSummonees` (призываемые в комментарии), `commentRequired`, `allowLinkCreation` и `elements` — поля с `required`, `defaultValue` и `description` |
| `postFunctions` | Массив объектов | Функции после перехода                                         |

Условия, функции и значения по умолчанию на экране записываются в формате API, ссылки — так же,
как в остальной выгрузке: пользователи — именем (`mapping/users.cfg`), группы и подразделения —
названием (`mapping/groups.cfg`), поля — ключом (локальные — `local_<ключ>`), очереди, статусы и
резолюции — ключом, компоненты и версии — названием, проекты — идентификатором (`id`) проекта из
выгрузки, роли — идентификатором. Рассылки записываются идентификатором рассылки в целевой
организации и передаются как есть.

Если API отклоняет воркфлоу с условиями, экранами и функциями или их не удаётся сопоставить —
например, группы из условия нет в целевой организации или пользователь не сопоставлен, — воркфлоу
создаётся только с переходами, как прежними версиями импорта, а в журнале появляется `Workflow …
is created without conditions, screens and functions of transitions` и причина. После импорта
всех очередей импорт пробует добавить условия, экраны и функции ещё раз: так переносится условие,
которое ссылается на очередь, импортированную позже. Если не вышло, в журнале появляется `Error
adding conditions, screens and functions to workflow …`; исправьте сопоставление и запустите
импорт снова — воркфлоу без условий, экранов и функций дополняется и при повторном прогоне.
Воркфлоу, созданные прежними версиями импорта, дополняются так же, если в выгрузке есть их условия,
экраны и функции. Дополнение заменяет переходы переходами выгрузки, поэтому названия и идентификаторы
переходов приводятся к выгрузке. Воркфлоу, где условия, экраны и функции уже есть, не меняется. Не
меняется и воркфлоу, шаги или переходы которого отличаются от выгрузки — статусом, целевым
статусом, видом (`actions` или `metaAction`) или числом: в журнале появляется `Workflow … differs
from the dump in transitions`, условия, экраны и функции задайте вручную. При сбое связи воркфлоу не создаётся и импорт останавливается, как раньше.

Функция `SetActiveSprintFunction` ссылается на доску идентификатором (`board`) из
[`boards.yaml`](./boards.md), значения по умолчанию на экране для полей `boards` и `sprint` — так
же: доски импортируются после очередей, поэтому воркфлоу с ними создаётся только с переходами и
дополняется после досок. Функция или значение по умолчанию с доской, которой нет в выгрузке,
пропускается с предупреждением. Настройки трудозатрат на экране перехода не переносятся.

## Структура `versions`

```yaml
- name: Version Name
  description: Version description
  startDate: '2020-05-10'
  dueDate: '2030-10-15'
  released: true
  releasedAt: '2030-10-20'
  archived: false
  next: Next Version Name
```

| Поле                                     | Тип        | Описание                                     |
|------------------------------------------|------------|----------------------------------------------|
| `name`<span style="color: red;">*</span> | Строка     | Название версии                              |
| `description`                            | Строка     | Описание версии                              |
| `startDate`                              | Строка     | Дата начала версии (формат `YYYY-MM-DD`)     |
| `dueDate`                                | Строка     | Дата завершения версии (формат `YYYY-MM-DD`) |
| `released`                               | Логический | Версия выпущена                              |
| `releasedAt`                             | Строка     | Дата выпуска (формат `YYYY-MM-DD`)           |
| `archived`                               | Логический | Версия в архиве                              |
| `next`                                   | Строка     | Название следующей версии этой же очереди    |

Версия с `released: true` и `releasedAt` создаётся сразу выпущенной этой датой. Следующая версия,
архив и выпуск остальных версий проставляются, когда созданы все версии очереди, — до импорта задач:
архивирование версии убирает её у задач без резолюции, а в архивную версию задача импортируется.
Версия, у которой в целевой организации уже есть задачи без резолюции (их создал прежний прогон), не
архивируется, в журнале появляется `Version … is not archived`. Версия с `released: true` без
`releasedAt`, а также созданная прежним прогоном невыпущенной, выпускается датой прогона. Пустое
значение `next` (`''` или `null`) снимает следующую версию; без ключа `next` она не меняется. Снятые
в выгрузке выпуск и архив у версии в целевой организации не снимаются.

## Структура `macros`

```yaml
- name: Macros name
  body: message text
  issueUpdate:
    description: New issue
    tags:
      add: "New tag"
  summonees:
  - Иван Петров
  summoneesFields:
  - assignee
- name: Field changes
  fieldChanges:
    priority: critical
    tags:
    - backend
```

| Поле                                     | Тип     | Описание                                                |
|------------------------------------------|---------|---------------------------------------------------------|
| `name`<span style="color: red;">*</span> | Строка  | Название макроса                                        |
| `body`                                   | Строка  | Сообщение, которое будет создано при выполнении макроса |
| `description`                            | Строка  | Описание макроса                                        |
| `issueUpdate`                            | Объект  | Объект со списком полей задачи, которые требуется изменить. Чтобы очистить поле, укажите значение `null`. Также допустимо использовать операторы `set`, `add`, `remove`; для полей с несколькими значениями — только `add` и `remove` (см. [Редактирование параметров](https://yandex.ru/support/tracker/ru/common-format#edit-fields)) |
| `fieldChanges`                           | Объект  | Новые значения полей: ключ поля — значение, которое заменяет текущее целиком, в том числе у полей с несколькими значениями. Вместе с `issueUpdate` не задаётся; локальные поля — только в `issueUpdate`. Проект — `{primary: <id>, secondary: [<id>]}`, номера проектов из выгрузки. Пользователь — именем, статус, приоритет, тип и резолюция — ключом, компонент и версия — названием |
| `summonees`                              | Массив  | Призываемые пользователи — именем (`mapping/users.cfg`)                  |
| `summoneesFields`                        | Массив  | Ключи полей с пользователями, которые призываются, например `assignee`; локальное поле — `local_<ключ>` |
| `maillistSummonees`                      | Массив  | Идентификаторы призываемых рассылок; в целевой организации нужна рассылка с тем же идентификатором |

## Структура `triggers`

```yaml
- name: Trigger name
  actions:
    - type: Transition
      status:
        key: open
  conditions:
    - type: CommentFullyMatchCondition
      word: Open
```

| Поле                                        | Тип             | Описание                                                            |
|---------------------------------------------|-----------------|---------------------------------------------------------------------|
| `name`<span style="color: red;">*</span>    | Строка          | Название триггера                                                   |
| `actions`<span style="color: red;">*</span> | Массив объектов | Массив с действиями триггера. Подробнее в разделе [Объекты действий триггера](https://yandex.ru/support/tracker/ru/concepts/queues/change-trigger-actions) |
| `conditions`                                | Массив объектов | Массив с условиями срабатывания триггера. Подробнее в разделе [Объекты условий срабатывания триггера](https://yandex.ru/support/tracker/ru/concepts/queues/change-trigger-conditions) |
| `active`                                    | Логический      | Статус триггера. <br>`true` - активный; <br>`false` - неактивный    |
| `description`                               | Строка          | Описание триггера                                                   |
| `skipFailures`                              | Логический      | Параметр `skipFailures` триггера в API, переносится как есть         |

Группы в условиях записываются не номерами, как в API, а названиями: в `value` у условий
`UserInGroups` и `UserNotInGroups` и в `groups` у `CommentAuthorInGroups` и
`CommentAuthorNotInGroups`. Импорт находит группу в целевой организации по названию; если там она
называется иначе, соответствие задаётся в `mapping/groups.cfg` (см. [docs/index.md](../index.md)).

Значения, которые ссылаются на объекты исходной системы, записываются так, чтобы импорт мог их
сопоставить:

- пользователи — именем, как в остальной выгрузке; соответствие задаётся в `mapping/users.cfg`.
  Так записываются `value` условий на поля с пользователями, `authors` у
  `CommentAuthorContainsAll`, `CommentAuthorContainsAny` и `CommentAuthorContainsNone`, `summonees`
  и пользователи в шаблоне полей `CreateIssue`;
- проекты — идентификаторами (`id`) проектов из выгрузки, импорт переводит их в номера целевой
  организации: в `value` условий
  `MultiProjectFieldEquals`, `MultiProjectFieldBecameEqual`, `MultiProjectContainerContainsAll`,
  `MultiProjectContainerContainsAny`, `MultiProjectContainerContainsNone` (`{"any": [68]}`), в
  действии `Update` поля `project` и в шаблоне полей `CreateIssue`
  (`{"primary": 65, "secondary": []}`);
- доски и спринты — идентификаторами (`id`) из [`boards.yaml`](./boards.md), импорт переводит их в
  номера перенесённых: в `value` условий на поля `boards` и `sprint` (число в условии на размер —
  не номер и не меняется), в действии `Update` этих полей, в фильтре автодействия, в шаблоне полей
  `CreateIssue` и в действии `SetActiveSprint` (`board: '148'`). Автоматизация с доской или
  спринтом, которых нет в выгрузке, не создаётся: без них она работала бы иначе. Исключение —
  действие `SetActiveSprint`: оно пропускается с предупреждением, как и функция перехода, а
  автоматизация создаётся, если у неё остались другие действия;
- виды связей в `linkFilter.relationship` у `AllLinkedIssueCondition`, `AnyLinkedIssueCondition` и
  `NoneLinkedIssueCondition` — идентификаторами: `relates`, `depends on`;
- локальные поля в `summoneesFields` и в шаблоне полей `CreateIssue` — ключом вида `local_<ключ>`.

```yaml
- name: Проверка по связанным задачам
  active: false
  skipFailures: true
  conditions:
    - type: AllLinkedIssueCondition
      linkFilter:
        relationship: [relates]
    - type: CommentAnyMatchCondition
      words: [готово, сделано]
  actions:
    - type: CreateIssue
      queue: SUPPORT
      summary: Проверить результат
      fieldTemplates:
        assignee: Иван Петров
        tags: [проверка]
```

Компоненты, версии и локальные поля в шаблоне `CreateIssue` сопоставляются в импортируемой
очереди, поэтому для задачи в другой очереди такой триггер не создаётся. Триггер с действием
`Duty` не создаётся. Макросы и автодействия импортируются после досок, триггеры — после задач.

Триггер и автодействие создаются неактивными, если после переноса они работали бы иначе:

- в условиях есть `AllLinkedIssueCondition`, `AnyLinkedIssueCondition` или
  `NoneLinkedIssueCondition` — фильтр по связанным задачам не переносится, только вид связи;
- у вебхука скрыты значения: `variables` записаны с именами и значениями `********`, `secrets` —
  списком имён, пароль или токен в `authContext` или в заголовке из `headers` — значением
  `********`. Переменные создаются с этими именами, секреты не создаются, заголовок создаётся со
  значением `********`.

Задайте значения в целевой организации и включите автоматизацию.

## Структура `local_fields`

```yaml
- category:
    en: System
    ru: Системные
  description: Have access to
  key: haveAccess
  name:
    en: Have access
    ru: Имеют доступ
  schema:
    type: array
    items: user
  optionsProvider:
    type: FixedUserListOptionsProvider
```

| Поле                                         | Тип        | Описание                                 |
|----------------------------------------------|------------|------------------------------------------|
| `key`<span style="color: red;">*</span>      | Строка     | Уникальный ключ поля                     |
| `name`<span style="color: red;">*</span>     | Объект     | Название поля на двух языках             |
| `category`<span style="color: red;">*</span> | Строка     | Категория поля на русском языке          |
| `schema`<span style="color: red;">*</span>   | Объект     | Тип поля                                 |
| `description`                                | Строка     | Описание поля                            |
| `optionsProvider`                            | Объект     | Объект с информацией об элементах списка |
| `readonly`                                   | Логический | Запрет редактирования поля               |
| `hidden`                                     | Логический | Скрытое поле                             |

Запрет редактирования и скрытие ставятся при создании поля; у поля, которое уже есть в целевой
организации, они не меняются. Поле с запретом API не принимает в действии «Вычислить по формуле»
триггера и автодействия, а глобальное поле — ещё и в действиях «Изменить значения полей» и
«Создать задачу» и в макросе. Поэтому на время создания такой автоматизации импорт снимает запрет
с полей, в которые она пишет, и сразу возвращает его, в том числе если создание не удалось. В
журнале это видно по строке `Field … is made editable while creating …`.

## Структура `schema`

```yaml
type: array
items: user
```

| Поле                                     | Тип     | Описание                                                                                               |
|------------------------------------------|---------|--------------------------------------------------------------------------------------------------------|
| `type`<span style="color: red;">*</span> | Строка  | Тип поля. В случае если поле является списком со множественным выбором, нужно указать значение `array`. Поля могут быть одним из следующих типов: <br>`date` — Дата; <br>`datetime` — Дата/Время; <br>`string` — Текстовое однострочное поле; <br>`text` — Текстовое многострочное поле; <br>`float` — Дробное число; <br>`integer` — Целое число; <br>`user` — Имя пользователя; <br>`uri` — Ссылка. |
| `items`                                  | Строка  | В случае, если поле является списком со множественным выбором, указывается тип данных элементов списка. В иных случаях - не указывается |

## Структура `optionsProvider`

### Структура `permissions`

| Поле            | Тип      | Описание                                          |
|-----------------|----------|---------------------------------------------------|
| `create`        | Объект   | Разрешения на создание задач в очереди            |
| `read`          | Объект   | Разрешения на чтение задач в очереди              |
| `write`         | Объект   | Разрешения на изменение задач в очереди           |
| `grant`         | Объект   | Разрешения на изменение настроек очереди          |
| `deny`          | Объект   | Запрет доступа к очереди: действует поверх остальных прав |

Каждый из объектов содержит перечень пользователей, групп, ролей, к которым применяется действие разрешения. Укажите в перечне хотя бы одно из полей:

| Параметр   | Описание              |
|------------|-----------------------|
| `users`    | Список пользователей  |
| `groups`   | Список групп          |
| `roles`    | Список ролей          |

#### Запрет доступа (`deny`)

Запрет действует и на учётную запись импорта, в том числе на администратора: под запретом она не
видит задачи и версии очереди. Поэтому:

- Запрет ставится в конце импорта отдельным запросом, в том числе после ошибки или Ctrl+C.
- Повторный прогон у очереди с задачами или версиями в выгрузке проверяет действующие права
  учётной записи импорта. Если запрет из выгрузки действует на неё — напрямую, через группу или
  роль руководителя или участника команды очереди, — эти субъекты снимаются (`Deny permission of
  queue … is lifted for the import account while importing`), импорт ждёт 30 секунд на каждую такую
  очередь и в конце возвращает запрет. До конца прогона снятые субъекты имеют доступ к очереди.
- Пока снятие не подействовало, отказ в доступе к задачам и версиям повторяется до минуты
  (`Access to queue … is denied, retrying in … s`).
- Запрет по роли в задаче (автор, исполнитель, наблюдатель) не снимается.
- Если запрет действует и через субъекты, которых нет в выгрузке, ничего не снимается: `Access to
  queue … is denied to the import account by a deny permission that is not in the dump`. Задачи,
  не созданные из-за отказа в доступе, отмечаются `Access to queue … is denied to the import
  account`.
- Если процесс импорта прерван аварийно, запрет остаётся снятым — запустите импорт ещё раз.
- Если запрет не удалось поставить (например, пользователя из него нет в целевой организации) —
  `Error updating deny permission for queue …`, поставьте его вручную. Снятая часть возвращается
  отдельным запросом и от этой ошибки не зависит.
- Группа, которой нет в целевой организации, пропускается: `Group … is not found, it is skipped in
  permissions of queue … (deny)`. Её участники под запрет не попадут.
