# Дашборды

**Файл для импорта:** `dashboard.yaml`  
**Расположение:** `./data/dashboards/<произвольный ключ>/dashboard.yaml`

Виджеты хранятся списком внутри этого файла: своего ключа у виджета нет — он создаётся в дашборде, а удаляется обновлением набора виджетов дашборда.

> Примечание: Поля, отмеченные звёздочкой (<span style="color: red;">*</span>), являются обязательными.

## Общие сведения

| Поле                                     | Тип             | Описание                                                                 |
|------------------------------------------|-----------------|--------------------------------------------------------------------------|
| `name`<span style="color: red;">*</span> | Строка          | Название дашборда                                                        |
| `layout`                                 | Строка          | Раскладка, например `two-columns`                                        |
| `owner`                                  | Строка          | Логин владельца. Если не указан, владельцем станет учётная запись импорта |
| `widgets`                                | Массив объектов | Виджеты дашборда                                                         |
| `id`                                     | Число           | Идентификатор в исходной организации. Информационное поле                 |
| `createdBy`, `createdAt`                 | Строка          | Информационные поля, при импорте не используются                         |

---

## Структура `widgets`

| Поле                                     | Тип             | Описание                                                            |
|------------------------------------------|-----------------|---------------------------------------------------------------------|
| `type`<span style="color: red;">*</span> | Строка          | Вид виджета (см. ниже)                                              |
| `description`                            | Строка          | Заголовок виджета                                                   |
| `color`                                  | Строка          | Цвет: `none`, `darkGreen`, `red`, `green`, `blue`, `yellow`          |
| `refresh`                                | Число           | Период обновления в секундах                                        |
| `filterParams`                           | Объект          | Условия отбора задач                                                |
| `fields`                                 | Массив строк    | Ключи полей задачи, которые показывает виджет                       |
| `column`, `row`, `order`                 | Число           | Положение виджета на дашборде                                       |
| `coords`                                 | Объект          | Координаты и размер: `x`, `y`, `w`, `h`                              |
| `collapsed`                              | Логическое      | Виджет свёрнут                                                      |

Остальные поля зависят от вида виджета и передаются как есть — например `text` у заметки, `perPage` у списка задач, `groupBy` у графика событий.

Виды виджетов: `filter`, `issues`, `table`, `table-sum`, `note`, `info`, `security`, `created-vs-resolved`, `burndown-chart`, `cycle-time`, `flow`, `velocity`, `time-since`, `goalFilter`, `projectPortfolioFilter`, `invite-links`, `orgAdmin`.

---

## Структура `filterParams`

Условия отбора задаются одним из трёх способов:

| Поле          | Тип          | Описание                                                                     |
|---------------|--------------|------------------------------------------------------------------------------|
| `filter`      | Объект       | Условия «поле — значение», например `{"queue": "FIRSTQUEUE"}`. Значения сопоставляются при импорте |
| `query`       | Строка       | Запрос на языке Трекера. Переносится **как есть**, см. ниже                    |
| `namedFilter` | Число        | Идентификатор сохранённого фильтра из `filters.yaml`                          |
| `sorts`       | Массив объектов | Сортировки: `field` — ключ поля, `ascending` — по возрастанию                |

Предпочтительна форма `filter`: её значения (очереди, статусы, типы, резолюции, пользователи) сопоставляются с целевой организацией по файлам из каталога `mapping`.

Форма `query` переносится без изменений: имена полей и значения в запросе не сопоставляются. Если в целевой организации нет поля с таким именем, виджет не создастся, и в журнале останется запись с текстом запроса. Запрос, который ссылается на отсутствующую очередь или незнакомый логин, создастся, но покажет пустой список — такой виджет проще поправить в интерфейсе Трекера.

Локальные поля очередей в фильтрах и виджетах не поддерживаются: локальное поле принадлежит очереди, а дашборд к очереди не привязан.

## Пример `dashboard.yaml`

```yaml
name: Мой дашборд
layout: two-columns
owner: user_login
widgets:
- type: filter
  description: Мои задачи
  color: green
  refresh: 7200
  perPage: 10
  fields:
  - summary
  - status
  filterParams:
    filter:
      queue: FIRSTQUEUE
    sorts:
    - field: updated
      ascending: false
  column: 1
  row: 1
  order: 0
  coords:
    x: 0
    y: 0
    w: 18
    h: 4
  collapsed: false
- type: note
  description: Как мы работаем
  text: Правила команды
  color: none
  column: 2
  row: 1
  order: 18
  coords:
    x: 18
    y: 0
    w: 18
    h: 11
```

## Особенности работы

1. **Создание идёт в три шага.** Сначала создаётся дашборд, затем каждый виджет, и в конце одним запросом задаётся расположение виджетов: при создании виджет положения не принимает.
2. **Повторный импорт не создаёт дубликатов.** Дашборд ищется по названию и владельцу, виджеты — по виду, заголовку и положению. Недостающие виджеты дозаливаются в уже созданный дашборд.
3. **Одноимённые дашборды одного владельца пропускаются**: различить, какой из них обновлять, невозможно, а создавать копию вслепую хуже. Такой дашборд нужно переименовать в выгрузке или перенести вручную.
4. **Поиск дашбордов работает с задержкой** в несколько секунд после создания или удаления. Два прогона подряд без паузы могут создать дубликат.
5. **Повторный импорт приводит набор виджетов к состоянию выгрузки.** Расположение задаётся полным списком виджетов, а он заменяет набор целиком: виджет, добавленный в целевой организации после импорта, при следующем прогоне удаляется. Исключение — дашборд, у которого не создался ни один виджет из выгрузки: тогда обновление не отправляется и существующие виджеты остаются на месте.
