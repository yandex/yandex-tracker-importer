# Сохранённые фильтры

**Файл для импорта:** `filters.yaml`  
**Расположение:** `./data/filters.yaml`

Все фильтры перечисляются в одном файле списком.

> Примечание: Поля, отмеченные звёздочкой (<span style="color: red;">*</span>), являются обязательными.

## Общие сведения

| Поле                                     | Тип             | Описание                                                                      |
|------------------------------------------|-----------------|-------------------------------------------------------------------------------|
| `id`<span style="color: red;">*</span>   | Число или строка | Идентификатор фильтра, уникальный среди фильтров всех выгрузок, которые импортируются из одного рабочего каталога: файлы `state/` у них общие. По нему виджеты дашбордов (`namedFilter`) ссылаются на фильтр, а повторный импорт находит созданный. Подойдёт любой — например, идентификатор фильтра в исходной системе |
| `name`<span style="color: red;">*</span> | Строка          | Название фильтра                                                              |
| `query`                                  | Строка          | Запрос на языке Трекера. Переносится как есть                                 |
| `filter`                                 | Объект          | Условия «поле — значение». Значения сопоставляются при импорте                 |
| `sorts`                                  | Массив объектов | Сортировки: `field` — ключ поля, `ascending` — по возрастанию                  |
| `fields`                                 | Массив строк    | Ключи полей, которые показывает фильтр                                        |
| `groupBy`                                | Строка          | Ключ поля для группировки                                                     |
| `filterType`                             | Строка          | Вид фильтра                                                                   |
| `owner`                                  | Строка          | Владелец. Информационное поле, при импорте не используется                    |

---

## Пример `filters.yaml`

```yaml
- id: 8
  name: Мои незакрытые задачи
  query: 'Assignee: me() Resolution: empty()'
  fields:
  - summary
  - status
  sorts:
  - field: updated
    ascending: false
```

---

## Особенности работы

1. **Владелец и права доступа не переносятся.** Создание фильтра их не принимает: владельцем станет учётная запись, от которой выполняется импорт, а права останутся по умолчанию.
2. **Повторный импорт не создаёт дубликатов**, но опирается на файл состояния. Перечисления фильтров в API нет, поэтому найти ранее созданный фильтр в целевой организации нечем: импортёр ведёт файл `state/filters.cfg` вида `исходный_идентификатор:созданный_идентификатор` и дополняет его сразу после создания каждого фильтра.
3. **Файл состояния нужно хранить рядом с выгрузкой.** Если он потерян, а импорт выполняется от той же учётной записи, фильтр с прежним названием не создаётся: названия фильтров уникальны у владельца, а найти фильтр прошлого прогона нечем. От другой учётной записи фильтр создаётся повторно. В журнале — ошибка `Filter named … already exists for its owner`: восстановите `state/filters.cfg` или переименуйте фильтр в выгрузке. Виджеты дашбордов, которые ссылаются на такой фильтр, не создаются.
4. **Локальные поля очередей не поддерживаются**: локальное поле принадлежит очереди, а фильтр к очереди не привязан.
