# Доски и спринты

**Файл для импорта:** `boards.yaml`  
**Расположение:** `./data/boards.yaml`

Все доски перечисляются в одном файле списком, спринты — внутри своей доски. Переносятся доски с
правилом добавления из условий по полям. Доски старого типа (состав задаётся фильтром или
запросом) не переносятся: сначала переведите их на новый тип.

> Примечание: Поля, отмеченные звёздочкой (<span style="color: red;">*</span>), являются обязательными.

## Общие сведения

| Поле                                     | Тип              | Описание                                                                                   |
|------------------------------------------|------------------|--------------------------------------------------------------------------------------------|
| `id`<span style="color: red;">*</span>   | Число или строка | Идентификатор доски, уникальный среди досок всех выгрузок, которые импортируются из одного рабочего каталога: файлы `state/` у них общие. По нему задачи и функции переходов ссылаются на доску, а повторный импорт находит созданную. Подойдёт любой — например, идентификатор в исходной системе |
| `name`<span style="color: red;">*</span> | Строка           | Название доски                                                                             |
| `columns`                                | Массив объектов  | Колонки: `id`, `name`, `statuses` — ключи статусов, `limit` — ограничение числа задач       |
| `sprintsAvailable`                       | Логическое       | Доска со спринтами и бэклогом                                                              |
| `estimateBy`                             | Строка           | Ключ поля, которым оцениваются задачи, например `storyPoints`                              |
| `autoFilters`                            | Объект           | Правила, по которым задачи сами попадают на доску и уходят с неё, — см. ниже               |
| `notes`                                  | Массив объектов  | Заметки колонок: `column` — `id` колонки, `text`                                           |
| `sprints`                                | Массив объектов  | Спринты доски — см. ниже                                                                   |
| `createdBy`                              | Строка           | Автор доски. Информационное поле: попадает в список досок, которым нужно открыть доступ    |

### `autoFilters`

`addFilter` — правило добавления: `enabled` и `fieldValues` — условия по ключам полей. Значение
условия — список `{fixed: <значение>, invert: <логическое>}` или `{macro: <макрос>, invert: ...}`:
очередь — ключом (`mapping/queues.cfg`), пользователь — именем (`mapping/users.cfg`), статус,
приоритет, тип и резолюция — ключом, компонент и версия — названием, проект — `id` из файлов
проектов. Макросы, например `empty()`, передаются как есть.

`removeFilter` — правило удаления: `enabled`, `statuses` — ключи статусов,
`checkResolutionPresence` — только задачи с резолюцией, `maxTimeInToRemoveState` — сколько задача
пробыла в статусе, например `P1W`.

### `sprints`

| Поле                                              | Тип              | Описание                                                        |
|---------------------------------------------------|------------------|-----------------------------------------------------------------|
| `id`<span style="color: red;">*</span>            | Число или строка | Идентификатор спринта, уникальный, как и у досок: по нему задачи ссылаются на спринт |
| `name`<span style="color: red;">*</span>          | Строка           | Название спринта                                                |
| `status`                                          | Строка           | `draft`, `in_progress`, `released` или `archived`               |
| `startDateTime`<span style="color: red;">*</span> | Строка           | Начало спринта                                                  |
| `endDateTime`<span style="color: red;">*</span>   | Строка           | Конец спринта                                                   |

## Пример `boards.yaml`

```yaml
- id: 137
  name: Команда разработки
  sprintsAvailable: true
  estimateBy: storyPoints
  columns:
  - id: 10
    name: Бэклог
    statuses:
    - open
    limit: 5
  - id: 20
    name: В работе
    statuses:
    - inProgress
  autoFilters:
    addFilter:
      enabled: true
      fieldValues:
        queue:
        - fixed: DEV
          invert: false
        resolution:
        - macro: empty()
          invert: false
    removeFilter:
      enabled: true
      statuses:
      - closed
      checkResolutionPresence: true
      maxTimeInToRemoveState: P1W
  notes:
  - column: 20
    text: Не больше трёх задач на человека
  sprints:
  - id: 22
    name: Спринт 1
    status: released
    startDateTime: 2026-01-05T00:00:00.000+0000
    endDateTime: 2026-01-18T00:00:00.000+0000
```

Задача ссылается на доски и спринты их идентификаторами: `boards: ['137']`, `sprint: ['22']` —
см. [описание задач](./issues.md). Так же — автоматизации, шаблоны задач и значения по умолчанию на
экранах переходов — см. [описание очередей](./queues.md).

## Особенности работы

1. **Доски импортируются после всех очередей, задачи — после досок.** Очереди из правила
   добавления должны быть в целевой организации. Статусы колонок и правил, типы и резолюции из
   условий создаются по `statuses.yaml`, `issue_types.yaml` и `resolutions.yaml`, если их нет.
   Статус может быть только в одной колонке: если статусы выгрузки из разных колонок сопоставлены
   с одним статусом, он остаётся в первой из них, в журнале —
   `Status … of board … is already in an earlier column`. Колонка, в которой не осталось статусов,
   не создаётся вместе с её заметкой, в журнале — `Column … of board … has no statuses left`.
2. **Права доски не переносятся**: доска создаётся закрытой. Список созданных досок со ссылками
   записывается в файл `boards_permissions.md` рабочего каталога — откройте доступ к каждой доске,
   как в исходной системе.
3. **Повторный импорт не создаёт дубликатов**, но опирается на файлы `state/boards.cfg` и
   `state/sprints.cfg`: названия досок и спринтов не уникальны. Доска или спринт создаются заново,
   только если созданных прежним прогоном нет. Настройки уже созданной доски повторный импорт не
   меняет, недостающие заметки колонок создаёт.
4. **Спринт создаётся с исходными датами начала и конца** и получает исходный статус. Статус
   ставится новому спринту и черновику прежнего прогона; статус, который поменяли в целевой
   организации, не перетирается. Автор, дата создания и дата закрытия спринта — новые. Пустой
   спринт, который доска со спринтами заводит сама, удаляется сразу после создания доски; если
   прогон прервался именно в этот момент, удалите его вручную.
5. **Доска или спринт, которые API отказывается создать** (например, очереди из правила добавления
   нет в целевой организации) или которые нельзя собрать из выгрузки (условие на локальное поле,
   нет обязательного поля), не создаются. Задачи импортируются без них — в журнале `Error importing
   …, its issues are imported without it` и у задач `Board or sprint … is not in the dump or cannot be
   created`. Если исправить причину и запустить импорт снова, доска создастся, но уже перенесённые
   задачи на неё не попадут. Ссылка на доску, которой нет в выгрузке, отбрасывается с тем же
   предупреждением. Если импорт очередей прервался ошибкой, отказ API не считается окончательным:
   доска могла ждать очередь, которая не успела импортироваться, — её задачи ждут повторного прогона.
6. **При любой другой ошибке** — сбой связи, ответ сервера 5xx, поле, статус или проект, которые не
   удалось найти или создать, — задачи доски не импортируются и переносятся повторным прогоном: в
   журнале `…, its issues wait for it: run the import again`. Так же — если какая-то очередь не
   импортировалась или `boards.yaml` не читается. Если причина не устраняется, исправьте её в
   выгрузке (справочник, `global_fields.yaml`) или уберите доску из `boards.yaml`: тогда задачи
   перенесутся без неё.
7. **Задачи, перенесённые прежними версиями импорта,** на доски и в спринты не попадают: повторный
   импорт уже существующие задачи не меняет.
8. **Не переносятся** права и владелец доски, быстрые фильтры, поля карточек, раскраска, дорожки
   и порядок карточек. Заметка колонки, которую не удалось создать, пропускается с ошибкой в журнале.
   В сохранённых фильтрах, дашбордах и в правиле добавления другой доски доски и спринты не
   переводятся в номера перенесённых.
