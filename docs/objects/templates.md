# Шаблоны задач и комментариев

**Файлы для импорта:** `issue_templates.yaml`, `comment_templates.yaml`  
**Расположение:** `./data/issue_templates.yaml`, `./data/comment_templates.yaml`

Шаблоны каждого вида перечисляются в своём файле списком: шаблоны очередей и личные шаблоны без
очереди.

> Примечание: Поля, отмеченные звёздочкой (<span style="color: red;">*</span>), являются обязательными.

## Общие сведения

| Поле                                     | Тип    | Описание                                                                             |
|------------------------------------------|--------|--------------------------------------------------------------------------------------|
| `id`<span style="color: red;">*</span>   | Число или строка | Идентификатор шаблона, уникальный среди шаблонов этого вида всех выгрузок, которые импортируются из одного рабочего каталога: файлы `state/` у них общие. По нему повторный импорт находит созданный шаблон. Подойдёт любой — например, идентификатор шаблона в исходной системе |
| `name`<span style="color: red;">*</span> | Строка | Название шаблона                                                                     |
| `description`                            | Строка | Описание                                                                             |
| `queue`                                  | Строка | Ключ очереди шаблона (`mapping/queues.cfg`). Без очереди — личный шаблон              |
| `owner`                                  | Строка | Владелец (`mapping/users.cfg`)                                                       |
| `permissions`                            | Объект | Права `READ`, `WRITE`, `GRANT`: у каждого `users`, `groups` (названия) и `roles` (`OWNER`, `QUEUE_TEAM_MEMBER`) |

Шаблон задачи:

| Поле             | Тип             | Описание                                                                                   |
|------------------|-----------------|--------------------------------------------------------------------------------------------|
| `fieldTemplates` | Объект          | Значения полей по ключам глобальных полей — как в шаблоне действия «Создать задачу»: пользователи — именем, компоненты и версии — названием, проекты — идентификатором (`id`) проекта из выгрузки (`primary`, `secondary`) |
| `checklistItems` | Массив объектов | Пункты чек-листа: `text`, `checked`, `assignee`, `deadline`                               |

Шаблон комментария:

| Поле                | Тип          | Описание                                             |
|---------------------|--------------|------------------------------------------------------|
| `template`          | Строка       | Текст комментария                                    |
| `summonees`         | Массив строк | Призываемые пользователи                             |
| `maillistSummonees` | Массив строк | Призываемые рассылки — идентификаторами рассылок в целевой организации, передаются как есть |

---

## Пример `issue_templates.yaml`

```yaml
- id: 13
  name: Ошибка
  queue: SUPPORT
  owner: Иван Петров
  fieldTemplates:
    type: bug
    priority: critical
    components:
    - Бэкенд
    assignee: Иван Петров
  checklistItems:
  - text: Приложить логи
    checked: false
  permissions:
    READ:
      roles:
      - QUEUE_TEAM_MEMBER
    WRITE:
      roles:
      - OWNER
    GRANT:
      roles:
      - OWNER
```

## Пример `comment_templates.yaml`

```yaml
- id: 3
  name: Нужны подробности
  owner: Иван Петров
  template: Опишите, пожалуйста, шаги воспроизведения.
  summonees:
  - Мария Иванова
  permissions:
    READ:
      groups:
      - Поддержка
```

## Особенности работы

1. **Повторный импорт не создаёт дубликатов**, но опирается на файлы состояния: названия шаблонов
   не уникальны, поэтому импортёр ведёт `state/issue_templates.cfg` и
   `state/comment_templates.cfg` вида `исходный_идентификатор:созданный_идентификатор`. Содержимое
   уже созданного шаблона повторный импорт не меняет. Шаблон создаётся заново, только если
   созданного прежним прогоном нет; при другой ошибке его чтения шаблон пропускается.
2. **Владелец сопоставляется через `mapping/users.cfg`.** Если владельца нет в целевой организации,
   шаблон не создаётся, в журнале — ошибка создания. Шаблон без владельца в выгрузке создаётся с
   владельцем — учётной записью, от которой выполняется импорт, в журнале `… has no owner in the
   dump`. Пользователи в полях, чек-листе и призываемые тоже сопоставляются через
   `mapping/users.cfg`: если кого-то из них нет в целевой организации, шаблон не создаётся.
3. **Права приводятся к выгрузке на каждом прогоне:** недостающие выдаются, лишние снимаются — в том
   числе права, которые API выдаёт новому шаблону по умолчанию (`READ` команде очереди, личные
   `WRITE` и `GRANT` создателю, если владелец — другой пользователь). Пользователь или группа, которых
   нет в целевой организации, пропускаются — в журнале `User … is not found` или `Group … is not
   found, it is skipped in permissions`, — и тогда пользователи или группы в этом праве не
   снимаются. Свои личные права импорт снимает, только если выполняется от администратора
   организации: иначе без них он не прочитает шаблон на следующем прогоне, в журнале — `…
   permission of the import account is kept`.
4. **Шаблон без `permissions`** получает права по умолчанию.
5. **Очередь шаблона** должна быть в целевой организации — импортироваться в том же прогоне или уже
   существовать. Её компоненты и версии ищутся по названию и тоже должны там быть, а тип задачи
   шаблона — быть в настройках этой очереди. Тип задачи и резолюция шаблона создаются по
   `issue_types.yaml` и `resolutions.yaml`, если их нет. Доски и спринты переводятся в номера
   перенесённых из [`boards.yaml`](./boards.md); поле с доской или спринтом, которых нет в выгрузке,
   пропускается с предупреждением.
6. **Локальные поля не переносятся**: API не принимает их в шаблоне задачи. Шаблон создаётся без
   них, в журнале — `Local field … is not imported`. Шаблон, у которого других полей нет, не
   создаётся: `… has no fields that can be imported`.
7. **Глобальное поле с запретом редактирования** API в шаблон не принимает: на время создания
   шаблона импорт снимает запрет и сразу возвращает его, в журнале — `Field … is made editable
   while creating Issue template …`.
8. **Метрики шаблона задачи не переносятся.**
9. **Рассылки** записаны идентификаторами рассылок в целевой организации и передаются как есть.
